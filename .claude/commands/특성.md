`demo13-flashlight`의 **캐릭터 특성(퍽) 시스템** 작업을 이어서 한다. 먼저 상태를 복원한 뒤 사용자가 준 초점으로 진행. (요약 짧게, 파일 덤프 금지.)

## 1. 현재 상태 (복원)
- **설계**: `docs/traits.md` — 진행형 퍽 트리 + 부정 특성(환급), 6 카테고리(전투·생존·회수·잠행·사회·★현상), **41개 퍽** 1차 수치(PP·티어·effects). effectKey 어휘·합성 규약도 §4.
- **코드**(전부 커밋됨):
  - `Assets/Scripts/Data/TraitData.cs` — SO(enum `TraitCategory`/`TraitTier`, `TraitEffect{effectKey,op,value}`).
  - `Assets/Scripts/Data/TraitManager.cs` — 싱글톤 런타임(로드/PP/CanUnlock·Unlock/GetModifier·GetAdditive·HasFlag/세이브). 말단 배선은 TODO.
  - `Assets/Editor/TraitDataImporter.cs` — **CSV→AssetDatabase 생성 메뉴** `Tools/TopDown/Data/특성 SO 재생성(CSV→AssetDatabase)`.
  - `Assets/Editor/Test/TraitManagerSelfTest.cs` — 자가검증 메뉴 `Tools/TopDown/테스트/특성 시스템 자가검증`.
  - `Assets/Editor/SystemsSceneBuilder.cs` — TraitManager 등록됨.
  - 데이터: `Assets/Resources/Data/Traits/*.asset` 41개, `tools/traits.csv`(진실), `tools/GenerateTraits.ps1`(구 손저작 — 폐기 예정).

## 2. 🔴 미해결 버그 (최우선)
**자가검증이 `[SO 41개 로드] expected=41 actual=0` 으로 실패.** `TraitManager.LoadDefinitions`의 `Resources.LoadAll<TraitData>("Data/Traits")`가 **0 반환**(41개 .asset이 폴더에 존재함에도).
- 시도했으나 실패: ① .asset 끝 개행 추가 ② CSV→AssetDatabase 재생성기.
- 디스크 검증은 통과: GUID(8c3730…) 41/41 일치, m_Script/EditorClassIdentifier 정상 SO와 동일, 경로·로드 코드도 기존 RecipeData 패턴과 동일.

## 3. 다음 진단 (이 순서로)
1. **임포터 실제 실행 확인**: 콘솔에 `✅ [TraitDataImporter] 특성 SO 41개 생성` 떴는지. 안 떴으면 그 메뉴부터 실행(기존 깨진 .asset 삭제 후 Unity가 직접 생성).
2. **범위 좁히기(핵심)**: self-test에 한 줄 추가해 같은 세션에서 `Resources.LoadAll<RecipeData>("Data/Recipes").Length`도 로그. → **0이면** edit-mode Resources 자체 문제 / **>0이면** TraitData 에셋·타입 한정 문제.
3. **로드 디버그**: `TraitManager.LoadDefinitions`에 로드 카운트+경로 로그, Awake에서 인스턴스가 Destroy되는지(Instance 충돌) 로그.
4. **에셋 인식 확인**: 재생성된 .asset 1개를 인스펙터에서 열어 스크립트가 `TraitData`로 잡히는지(노란 "missing script" 아닌지).
5. 해결되면 **재생성된 .asset 41개 커밋** + `GenerateTraits.ps1` 폐기, traits.md 결정 로그 기록.
