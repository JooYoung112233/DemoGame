기존 게임(타르코프/좀보이드/낙원) 대비 **갭 분석에서 채택한 기능 10종**을 **정해진 통합 순서대로** 한 번에 하나씩 이어서 구현한다. (요약 짧게 — 파일 덤프 금지.)

## 통합 구현 순서 (고정)
①설정 메뉴 → ②적 시체 루팅 → ③퀵슬롯 → ④무게 초과 페널티 → ⑤소음 시스템 → **⑥투척물** → ⑦상인 재고 회전 → ⑧시체 회수(시간 잔상) → ⑨아이템 도감 → ⑩지도+시계 나침반

> 진행 상황의 진실 = `demo13-flashlight/docs/dev-roadmap.md` 변경 로그의 "갭 분석 통합 순서 구현 진행" 줄 + 각 시스템 md의 "✅ 구현 완료" 표기.

## 1. 상태 로드 (먼저, 병렬로)
- `git -C <repo루트> fetch` 후 `git rev-list --left-right --count origin/feature/demo13-flashlight...HEAD` — **원격이 앞서면(집/회사 병행 or 병렬 프로세스) 먼저 pull**. `git log --oneline -8` + `git status -s`.
  - ⚠️ 이 브랜치엔 **병렬 자동커밋 프로세스**가 돌아 `git add -A`로 내 미커밋 변경을 쓸어담을 수 있음. 커밋은 **항상 파일 경로 지정**(`git commit -- <paths>`)으로, 커밋 전 `git diff --cached --name-only` 확인. GPT 폴더·씬·프리팹 대량 변경은 병렬분이니 제외.
- `dev-roadmap.md` 진행 로그에서 **마지막 완료 번호** 확인 → 다음 번호가 이번 작업.
- 해당 기능의 시스템 md(설계/결정) 확인: 무게·퀵슬롯·도감=`inventory.md`/`items.md`, 시체루팅·소음·투척물=`combat.md`, 시체회수·지도=`raid.md`, 재고회전=`economy.md`, 설정=`dev-roadmap.md`. 수치는 `GameTuning` + `balance.md` 색인.

## 2. 요약 후 진행
- 어디까지 됐고 **다음 항목이 뭔지 2~3줄** 요약.
- `$ARGUMENTS` 있으면 그 항목, 없으면 **다음 미완 순번**.
- **기획 결정/방향이 필요하면 AskUserQuestion으로 먼저 확정**(설계 임의결정 금지). 특히 UI 표현(⑥투척물 조준·⑨도감 레이아웃·⑩지도 형태)은 물어보고 진행.
- 구현 = 코드 작성 → 정적 컴파일 감사(브레이스·시그니처 실재·using) → **unity-reviewer 리뷰**(백그라운드) → 지적 반영.
- **테스트 수단 동반 필수**: 검증하기 어려운 상태는 `DebugTestUI.cs`(F1) 버튼을 같은 작업에 추가 (예: 무게=납덩이 지급, 소음=큰소음 발생). [[feedback-test-tooling-with-features]]

## 3. 고정 원칙
- 신규 .cs는 **.meta도 생성**(GUID). 자가부트 UI/시스템은 QuickSlotBar/PlayerNoise 패턴(부팅 싱글턴 + DontDestroyOnLoad).
- 안전가옥(허브) 면제가 필요한 페널티/소음은 `UIManager.IsSafehouse` 기준(‘활성 지역 없음’ StaminaInfinite은 F1 직행 시 오작동).
- **기획 결정 즉시 `docs/` md 기록**(날짜/질문/결정) + 완료 시 "✅ 구현 완료" 표기. 밸런스는 GameTuning/Control Panel + balance.md 색인.
- `main` 직접 push 금지(브랜치→PR). 커밋·푸시는 **사용자 요청 시만**. 메시지 끝: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
