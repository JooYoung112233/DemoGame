`demo13-flashlight` **게임 시스템 빌드**를 한 단계 이어서 진행한다. (요약은 짧게 — 파일 덤프 금지.)

## 1. 상태 로드 (먼저, 병렬로)
- `demo13-flashlight/docs/dev-handoff.md` — **지금 위치 / 다음 코드 후보 / 테스트 체크**(여기부터).
- `git fetch` 후 `git rev-list --left-right --count origin/feature/demo13-flashlight...HEAD` — **원격이 앞서 있으면(다른 PC 병행) 먼저 pull**(미커밋 작업은 stash→pull→pop). `git log --oneline -5` + `git status -s`.
- 필요시 `demo13-flashlight/docs/dev-roadmap.md` 빌드 순서표 / 관련 시스템 md.

## 2. 요약 후 진행
- 현재 어디까지 됐고 **다음 한 단계가 뭔지 2~3줄**로 요약.
- `$ARGUMENTS` 가 있으면 그 항목을, 없으면 dev-handoff "다음 코드 후보" 1순위를 진행.
  - 큰 기능이거나 기획 결정이 필요하면 **AskUserQuestion으로 방향만** 먼저 확정(설계 임의결정 금지).
- 진행:
  - 코드면 → 작성 + **정적 컴파일 감사**(브레이스 균형·타입/시그니처 실재·using 정합) + 필요시 unity-reviewer. Unity 못 돌리니 여기까지가 내 몫.
  - 씬/그레이박스/에셋이면 → 돌릴 빌더(`Tools ▸ TopDown ▸ 빌드 ▸ …`)·연결 단계를 사용자에게 안내.

## 3. 고정 원칙
- **리소스(아트)만 제외, 그 외 전 게임 시스템을 그레이박스로 한 단계씩 제작+테스트.**
- **Unity 실행/테스트는 사용자** → 결과(특히 컴파일 에러=0순위) 받고 다음 단계.
- 플레이어 경험 순서: **타이틀 → 안전가옥 → 레이드 → 루팅 → 전투 → 시스템.**
- **기획 결정은 즉시 해당 `docs/` md에 기록**(날짜/질문/결정). 모든 밸런스는 GameTuning/Control Panel + balance.md 색인으로 통일.
- `main` 직접 push 금지(브랜치→PR/푸시). **커밋·푸시는 사용자가 요청할 때만.** 커밋 메시지 끝: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.

## 4. 마무리
- 단계 끝나면 `dev-handoff.md`의 "지금 위치 / 다음 코드 후보 / 테스트 체크"를 갱신해 다음 핸드오프를 남긴다.
