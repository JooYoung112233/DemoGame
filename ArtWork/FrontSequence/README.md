# 앞단 플레이 시퀀스 검증 — 2026-09-13

## 판정

**기능별 진입은 확인, 신규 유저 스토리 시퀀스는 미통과.**
타이틀 → 빈 슬롯 새 게임 → S-000/S-001 → 하이드아웃 왕복/장비 착용 → 마을 관리인 → 전당포 실내 대화/거래 → 출전 지도/의뢰 → Zone1 진입과 첫 이동까지 실행했다.

Unity 6000.6.0f1, Demo/demo13-flashlight, 1920×1080 Game View. `QA_ENABLED`는 꺼진 채 유지했다. MCP `run_script`에서 `GameInput` 이동·E·Space·ESC·우클릭을 사용했고, uGUI 버튼은 실제 `onClick` 리스너를 호출했다. OS UI 자동화·씬 전환 API·플레이어 순간이동·테스트 장비 주입을 사용하지 않았다. 마우스 EventSystem의 실제 히트 테스트 전체를 검증한 것은 아니다.

## 남은 진행/콘텐츠 문제

1. **첫 대면 → 암구호 → 회수꾼 → 첫 의뢰 연결이 중단되어 있다.**
   - 신규 슬롯에서 전당포를 걸어서 들어가 E: `팔 거라도 있나?` 일반 거래 대화가 나옴 (`25`, `26`, `27`).
   - `StoryTriggerManager.TryPlayNPCStoryScene`의 전당포 분기가 `스토리 비활성 (그레이박스 테스트)` 상태. 회수꾼 S-003/S-004는 `got_password_ember`가 있어야 시작한다.
   - `StoryState.json`: safehouse_arrived만 true, active/completed quest 없음. 의뢰 게시판 실제 화면에도 붙은 의뢰 없음 (`41`).
   - 기존 테스트용 비활성 정책은 이번 QA에서 변경하지 않았다. 회수꾼 대화 자체를 추가 실플레이한 것은 아니며 후속 차단 원인은 코드 조건으로 확인했다.
2. **창고라는 이름과 첫 보관함 접근이 불일치.** 시설 창고는 Lv0 건설(스크랩 10,000/재료 요구), 기본 보관함은 별도의 인벤토리 버튼으로 접근된다. 초반 지급 권총/방망이/탄창/탄약 4칸은 정상 존재. 진행 불가가 아닌 안내/발견성 문제 (`06`, `08`, `51`).
3. **출전 후 첫 화면의 방향 단서 부족.** Zone1 `(277.1,0,163.2)` 진입은 성공, 20분 타이머·도입 대화·그 뒤 걷기도 정상. 화면이 회색 지형 위주이고 첫 의뢰가 없어 초반 목표가 약하다 (`44`, `46`). 맵 전체가 비어 있다고 판정한 것은 아니다.
4. **초반 가방/보급 안내 공백.** 새 게임 인벤토리에 가방 미장착, 소지품 0, 장비는 창고에 있다. 가방 확보·두 무기 동시 휴대·의료품 준비 안내는 추가 검증/정리가 필요하다. 이번에는 지급된 권총과 방망이를 각각 착용했으며, 방망이 착용 때 권총은 창고로 돌아갔다.

## 확인된 기능

- 정상 타이틀/빈 슬롯 새 게임 버튼 → 마을 기본 스폰 `(53.5,0,12)`.
- S-000/S-001 입력 진행 및 종료. 수정 후 첫 대사 가시성.
- 걷기로 하이드아웃 입장, 시설 UI, 인벤토리/기본 보관함, 지급 무기 우클릭 착용.
- 나가기 버튼 → 확인 → 마을 `(54.2,0,12)` 복귀.
- 관리인 E 대화. 전당포 걷기 진입/실내 이동/E 대화 → 거래 선택 → 거래창 → ESC 닫기.
- 마을 미니맵 표시. 출전 지도판 E → 지역 선택 → 실제 출전 버튼 → Zone1 → 첫 걷기.

거래창 열기까지만 검증했으며 실제 구매/판매, 저장 후 이어하기, 레이드 루팅·전투·탈출·정산은 범위 밖이다.

## 기록 해석 / QA 도구 교정

- 번호별 JSON의 `success`는 해당 입력 실행/목표 도달 결과다. UI의 의미적 성공은 `before/after`와 스크린샷으로 별도 판정했다.
- `05`: 문 트리거로 정상 Hideout에 들어간 뒤 이전 씬 목표를 계속 추적해 발생한 도구 오탐. 씬이 바뀌면 걷기 종료하도록 고쳤고 `49` 재검증 통과.
- `18~20`: 하네스가 ESC Down을 2프레임 유지해 대화 닫기 후 Pause까지 연 오탐. 프레임 플래그를 매 프레임 정리하도록 수정. 이후 거래창 ESC(`28`)는 UI/일시정지 없이 정상 닫힘. 게임 버그로 집계하지 않음.
- `22/29/31/33/35/37`: 직선 목표 경로에서 벤치·볼라드·게시판·모래주머니에 막힘. 화면 및 콜라이더 확인 후 옆으로 걸어서 우회. 지도판 도달 불가 결함으로 집계하지 않음. 최종 `39/40` 정상 도달/지도 표시.
- 재현용 `Play.cs`는 `Command.json`의 단일 `{label,op,...}` 또는 `steps` 배열을 실행. 실제 진행은 번호별 JSON에 보존했다. 자동 경로 탐색기가 아니므로 새 레이아웃에서는 웨이포인트를 다시 확인해야 한다.

## 저장/에디터 복원

- 슬롯 0에 실제 저장 존재, 슬롯 1/2 비어 있음을 먼저 확인했다. 슬롯 1 새 게임만 사용했고 전 과정 `SuppressWrites=true`.
- `SaveHashesBefore.json`/`SaveHashesAfterPlay.json`/`FinalEditorState.json`에서 실제 save_0의 SHA-256 동일. 테스트 슬롯 파일도 생성되지 않았다.
- 종료 후 원래 **Play 정지 / Systems 활성 + Safehouse additive / 두 씬 dirty=false**로 복원. `Virtual=false`, `SuppressWrites=false`.
- 플레이 검증은 MCP만 사용했고 씬/프리팹 에셋 수정 없음.
