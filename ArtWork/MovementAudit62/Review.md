# 플레이어 이동 모션 속도 검수 — 2026-09-12

요청: “지금 걷기, 달리기, 등 이동하는 모든 모션의 속도 한번 체크해줘”. 읽기 전용 검수이며 게임 수치·클립·씬을 변경하지 않았다.

## 확인 범위와 한계

- Unity MCP로 Safehouse 플레이 중 실제 PlayerRig, StatDB, Animator와 저장된 프리팹을 읽었다. 결과는 `Inspect.json`.
- 별도 Unity PreviewScene에서 실제 캐릭터 프리팹·스케일로 Walk, Run, SwordWalk, BatWalk를 주기당 240구간 샘플링했다. 결과는 `FootSamples.json`. 종료 시 PreviewScene을 닫았다.
- 사용자의 입력을 대체하거나 플레이어를 이동시키지 않았다. 모든 상태를 실제 조작해 달린 거리 측정은 수행하지 않았다. 아래 이동 속도는 확인한 실행 스탯과 이동 공식으로 계산한 목표 속도이며, 충돌·가감속 중 순간 속도는 다를 수 있다.
- 최종 재조회에서는 플레이어의 런타임 Animator가 없어 재측정하지 못했다. 결과는 앞서 성공적으로 확보한 실행 스냅샷 기준이다. 검사 도구에 플레이어 부재 및 비실행/비초기화 상태 가드를 추가했다.

## 현재 목표 속도와 모션

부착물·과적 보정 없는 기본값, 단위 m/s. 걷기 계열 1주기는 좌우 발이 한 번씩 움직이는 전체 루프다.

| 상태 | 목표 속도 | 다리 모션 / 전체 주기 | 재생 배속 |
|---|---:|---|---:|
| 맨손 걷기 | 4.00 | Walk / 1.20초 | 1.0 |
| 맨손 달리기 | 6.40 | Run / 0.80초 | 1.0 |
| 맨손 웅크려 이동 | 2.00 | 일반 Walk / 1.20초 | 1.0 |
| 검·방망이 걷기 | 4.00 | SwordWalk·BatWalk / 1.20초 | 1.0 |
| 검·방망이 달리기 | 6.40 | Run / 0.80초, 무기 수납 | 1.0 |
| 권총 걷기 / 달리기 | 4.00 / 6.40 | Walk / Run | 1.0 |
| 소총 걷기 / 달리기 | 3.68 / 5.888 | Walk / Run | 1.0 |
| 권총 조준 이동 | 2.40 | Walk 다리 + 조준 상체 | 1.0 |
| 소총 조준 이동 | 1.84 | Walk 다리 + 조준 상체 | 1.0 |
| 근접 강공격 차징 이동 | 1.60 | 걷기 계열 | 1.0 |
| 약공격·강공격 타격 중 | 0 | 공격 모션 | 이동 정지 |

웅크리기 ×0.5와 차징 ×0.4는 해당 상태의 이동 속도에 곱해진다. 따라서 권총 조준+웅크리기는 1.20, 소총은 0.92m/s다. 조준·재장전·웅크리기 중에는 달리기가 차단된다. 총기 걷기 상체 클립도 1.20초이며, 하체 본은 일반 걷기에서 유지된다. 총 꺼내기/수납 전환은 별도로 약 1.20초다.

과적 시 레이드에서 ×0.85 또는 ×0.70, 달리기 차단. 안전가옥에서는 무게 페널티를 적용하지 않는다. 가속 45m/s², 감속 80m/s²이고 대각선 입력은 정규화되어 직선보다 빨라지지 않는다.

구르기는 GameTuning 기본값상 비활성이다. 이번 실행 스냅샷에는 활성 플래그를 수집하지 못했으므로 런타임 활성 여부는 확정하지 않는다. 활성화할 경우 현재 스탯 3m/0.3초와 감쇠 배율 1.35→0.5로 목표 속도 13.5→5m/s이며, 현 3D 경로는 전용 구르기 대신 Run을 선택한다.

## 접지 샘플 분석

클립은 모두 제자리 애니메이션이며 root motion을 쓰지 않는다. 실제 모델 스케일 1에서 발 본이 가장 낮은 높이의 15% 이내(최소 1cm 허용)에 있고 뒤로 움직이는 구간을 추출했다. 이 수치는 접지 판정 방식에 의존하는 추정치이며 유일한 정답 속도가 아니다.

| 클립 | 왼발 접지 평균 / 중앙값 | 오른발 접지 평균 / 중앙값 |
|---|---:|---:|
| Walk | 0.464 / 0.490 | 0.464 / 0.490 |
| SwordWalk | 0.464 / 0.490 | 0.464 / 0.490 |
| BatWalk | 0.464 / 0.490 | 0.464 / 0.490 |
| Run | 2.155 / 2.240 | 1.898 / 2.076 |

걷기 4m/s는 접지 평균 약 0.46m/s의 약 8.6배, 달리기 6.4m/s는 접지 추정 약 2.0~2.2m/s의 약 3배다. 현재 재생 속도 1배에서는 발 미끄러짐을 유발할 큰 불일치가 있다. 달리기는 좌우 접지 속도도 차이가 있어 단일 배속 조절만으로 양발을 완벽히 고정할 수 없다.

## 판정

1. 실제 PlayerRig와 저장 프리팹의 `animCadenceMatchesSpeed=false`. `MotionStat.animSpeed`는 모두 1이며 Animator state와 BlendTree timeScale도 1이다. 속도 연동 코드가 있어도 현재 설정에서는 사용하지 않는다.
2. `walkClipSpeed=0.34`, `runClipSpeed=0.52`는 현재 비활성 기준값이다. 특히 달리기 값이 측정 결과와 크게 다르므로 연동 토글만 켜는 수정은 적절하지 않다. 배속 상한 2.4 때문에 현재 이동 속도를 모두 보상할 수도 없다.
3. 웅크리기 입력은 이동 속도만 낮춘다. 3D 모션 선택에는 crouch/crouch_walk 분기가 없고 컨트롤러에도 해당 클립이 없다.
4. 조준 상태에서는 커서 방향을 바라본 채 일반 전진 Walk 다리 모션을 쓴다. 후진·옆걸음 전용 모션이 없어 이동 방향과 발 동작이 어긋날 수 있다. 일반 이동은 이동 방향으로 캐릭터를 직접 회전시킨다.
5. 검·방망이 걷기는 일반 걷기와 같은 하체 궤적·주기라 속도 불일치도 동일하다. 소총·조준·과적의 이동 감속에도 현재 재생 배속은 1로 유지된다.
6. 검수 당시 `docs/combat.md`에는 걷기 0.45, 달리기 약 2.295m/s와 연동 활성화 결정이 기록돼 있었지만, 이번 실행/프리팹 값에는 반영되지 않았다. 진행 중인 별도 변경을 덮어쓰지 않았다.

## 재현 도구

프로젝트 루트에서 `tools/unity_mcp_call.py run_script`에 이 폴더의 `tools/inspect.json` 또는 `tools/sample.json`을 전달한다. Unity gameplay 씬에 TopDownPlayer가 존재해야 한다. 도구는 MCP `run_script`로 메모리에서 실행되며 Assets에 스크립트를 임포트하지 않는다.

결론: 이동 속도와 원본 모션 속도가 맞지 않는 상태다. 이번 요청 범위는 검수이므로 밸런스 수치는 변경하지 않았다.
