# 마을 내부 — 작은 영업 공간과 잠긴 추가 방

> **2026-09-13 현재:** 이 패키지를 Unity 마을 5개 상점에 연결했다. 실제 적용·좌표 보정·Comic B 재질·통행 검수는 [InteriorIntegration62](../InteriorIntegration62/README.md)를 참조한다. 아래는 오프라인 제작 당시의 구조와 검토 이력이다. 추가 방 해금 기능은 여전히 후속이다.

2026-09-11 사용자 결정: 외곽은 유지하고 내부 일부를 창고·폐쇄 구역으로 구분한다. 현재는 막아두며, 나중에 기능 해금 때 **내부 문을 열어 추가 방에 진입하는 방식**으로 확장한다. 칸막이를 철거하는 방식은 폐기했다.

현재 산출물은 Assets 밖의 Blender/FBX 모델과 연결용 데이터다. Unity 플레이·기존 외곽·NPC·실행 에셋은 변경하지 않았다. 실제 게임에서 이미 잠금/해금이 동작한다는 의미가 아니다.

| 건물 | 유지한 외곽 | 현재 영업 공간 | 잠긴 추가 방 면적 |
|---|---|---|---|
| 전당포 | 16×12m | 9×6m = 54m² | 138m² |
| 수리점 | 14×10m | 7.5×6m = 45m² | 95m² |
| 의료소 | 18×10m | 8×6m = 48m² | 132m² |
| 가구점 | 10×14m | 7×7m = 49m² | 91m² |
| 암시장 | 12×14m | 7×6m = 42m² | 126m² |

면적은 외곽 기준의 배분값이며 벽 두께를 뺀 유효 바닥 면적이 아니다. 영업 공간 치수는 제작 시안으로 사용자 최종 승인을 기다린다.

원화는 이전 패키지 `../TownInteriors62/ReferenceIndex.jpg`, `ExteriorReferences.jpg`를 통해 GPT 건물별 외형/내부를 재대조했다. 전당포의 앞 진열장/뒤 선반, 수리점 작업대 한 세트, 의료소 진료대 한 세트, 가구점 식탁/의자, 암시장 천 판매대를 유지했다. 가구 크기와 PBR 그래프는 원본 그대로이며 러그 외 배치 스케일은 1이다. 자체 검수에서 암시장 천 끝의 계단 모양을 발견해 해당 천만 연속된 가장자리로 보완했다. 원본 패키지는 수정하지 않았다.

## 모델 구조

- `BlenderSource~/TownInteriors62.blend`: 편집 가능한 라이브러리와 각 `*_Assembly62` 배치.
- `Models/StorageDoorLeaf62.fbx`: 바닥 경첩 위치가 원점인 공용 문짝. Unity 로컬 Y축 -90° 회전으로 추가 방 방향으로 열린다.
- `*_RearLining62`, `*_LeftPartition62`, `*_RightPartition62`: 실제 1.2×2.26m 문 구멍을 가진 고정 칸막이. 문틀과 낮은 문턱 포함. 해금해도 유지한다.
- `*_Rear/Left/RightClosureRoof62`: 각 잠긴 방의 독립 덮개. 외곽 지붕을 가려도 잠긴 방 덮개는 남긴다.
- `*_Rear/Left/RightClosedFloor62`: 추가 방의 기본 바닥. 해금 기능에 필요한 가구/인테리어는 아직 없다.
- `*_RoomDividers62`: 추가 방 사이의 고정 벽. 한 방을 열고 다른 잠긴 방을 우회 진입하지 못하게 분리한다.
- `*_ClosedFrontReturn62`: 폐쇄 구역의 전면 가림. 원래 외곽이 실내 가림 대상이 될 때 빈 틈을 노출하지 않기 위한 내부 마감.
- `*_PreviewCutaway62`, `*_OuterOutline62`: 미리보기 전용, 게임 씬에 중복 배치하지 않는다.

## 연결 데이터

`KitManifest.json`은 외곽 기준 미터 좌표를 사용한다. `buildings`의 외곽/문 폭 1.6m/월드 위치와 yaw는 이전 패키지와 동일하다. `serviceCenterZ`로 영업 공간을 기존 정문에 맞췄다. 가구점/암시장은 기존 월드 yaw 90°이며 개별 이미지에서는 입구가 아래를 향한다.

`expansionZones`에는 건물별 `pawnshop.rear`, `pawnshop.left` 같은 안정적인 ID 총 15개, 초기 `locked`, 구역 차단 박스, 문 피벗/배치 인덱스, 문틀/바닥/덮개, 문 앞 접근점이 있다. 해금 조건은 `null`이다. 벽은 유지하며 문 잠금 해제, 문 개방, 입실 시 해당 덮개 가림, 구역 차단 해제가 후속 연결 대상이다. 해금 순서·비용·기능명·세이브 형식은 정하지 않았다.

기존 전당포 NPC 로컬 `(0,0,2.4)`는 이제 폐쇄 영역에 걸릴 수 있다. Unity 연결 시 `buildings.approachTargets`와 새 카운터 위치를 기준으로 NPC/상호작용 지점을 함께 옮겨야 한다. 현 씬의 NPC 위치를 바꾼 것은 아니다.

## 검증과 남은 작업

`ModelValidation.json`: UV/표면/원본 해시, 외곽·정문 정렬, 가구 스케일, 입구부터 카운터 및 잠긴 문 앞까지 반경 0.35m 보행자를 가정한 평면 통행 검사. 실제 콜라이더 규격이나 NavMesh 검증은 아니다.

`DoorValidation.json`: 15개 구역의 초기 잠금·독립 ID·힌지 원점과 실제 메시를 확인한다. 문마다 9개 광선으로 닫힌 문 차단, 고정 벽의 통로 개방, 90° 열린 문 통과를 검사한다. `FBXValidation.json`은 가구/천/재사용 모델과 새 칸막이/덮개 등의 재임포트 UV·크기 검사다.

실제 Unity GameLit 조명, 90° 방향 가구점/암시장의 인게임 가림, 충돌/NavMesh, NPC 상호작용, 해금/세이브 로직은 Unity MCP로 연결한 뒤 검증해야 한다. 문 구멍을 막지 않도록 칸막이 콜라이더는 좌우 벽/상인방으로 나눠야 하며 전체 bounds 하나의 BoxCollider를 씌우면 안 된다.
