# 측면 몸 보조광 보정 — 2026-09-11

사용자 측면 캡처: “여전히너무 밝은ㄷ것같은데”. 앞선 가방의 LampSpill 보정 후 남은 팔·목의 과조명이다. 기존 PlayerRig BodyGlow .35/카메라쪽.8m가 원인으로 재현됐다.

- `Before_*`: 이번 변경 전 양측면(90/270°) 낮밤. 앞선 가방 보정은 적용된 상태다.
- `NoGlow_*`: BodyGlow만 끈 비교. 팔·목의 밝은 얼룩이 사라진다.
- `NoSpill_*`, `NoBeam_*`: 원인 분리용 비교. 앞선 발밑 퍼짐광/전방 빔을 각각 끈다.
- `SoftFill_*`: 채택 후보(.06/1.1m).
- `Saved_*`: 프리팹 저장 및 현재 인스턴스 반영 후, 45° 간격 8방향 낮밤 자체 검수 16장. 실제 플레이어 모델에 임시62° 확대 카메라(ortho1.7)를 사용한다. 모델/빔 회전과 환경·광원 상태는 호출 종료 시 복원한다. 일반 Main Camera 캡처나 UI 비교는 아니다.
- `Validation.json`: 디스크 프리팹과 라이브 값, 낮밤 적용, 광원 실제 월드 위치, GameLit 오류0 확인. 플레이는 유지했으며 재시작 검증은 하지 않았다.

BodyGlow 세기 .35→.06, 카메라쪽 거리 .8→1.1m. 높이.1/반경1.6/발밑 퍼짐광/전방 빔/환경과 재질은 유지. .02/1.2m의 첫 후보는 밤 실루엣이 너무 어두워 수정했다. 실제 PlayerRig 직렬화 값만 변경하며 기존 C# 필드 기본값은 그대로다.

재현은 Unity MCP의 run_script에 tools/*.json 전달. `diagnose.json`은 현재값을 기준으로 Before를 다시 쓰므로 기존 자료를 덮어쓰지 말 것. 모델을 돌려도 보조광은 실제 LateUpdate와 같은 카메라 쪽 월드 위치로 맞춘다. 이전 BackpackLight62 앞뒤 검사에서 이 동기화와 측면 확인이 부족했으므로 몸 조명 판단은 이번 자료가 우선한다.

자체 검수와 사용자 최종 외형 승인은 구분한다. 하이드아웃 실제 화면, 모든 주변 조명 조건, 연속 이동 및 모든 장비 등급 시각 검수는 이번 범위 밖이다.
