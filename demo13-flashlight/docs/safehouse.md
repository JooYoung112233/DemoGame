# 안전가옥 시스템

> 탐사 정보 루프(라디오 · NPC 파견 · 랜드마크 인텔)는 [`safehouse-intel.md`](safehouse-intel.md) 별도 문서.

## 현재 상태: 방향 확정 + 확장 기획 확정

## 확정된 방향

**덕코프식 물리 공간 + 오브젝트 배치 성장**

- 컨테이너 1개를 탑다운 물리 공간으로 구현
- 플레이어가 직접 걸어다니며 시설과 상호작용
- 업그레이드 = 같은 컨테이너에 시설 오브젝트가 추가/개선되는 방식
- 방 자체를 바꾸지 않음 (낙원식 등급별 방 변경 X)
- 복잡한 정보(제작 레시피, 업그레이드 트리 등)는 메뉴 UI로 처리
- 기존 탑다운 이동/상호작용/조명 시스템 재활용

## 맵 레이아웃: 뒷골목 (Back Alley)

### 컨셉 (2026-06-02 개정: 공터 → 골목+건물)

안전가옥 = **ㄱ/T자로 꺾인 폐도시 골목길**. 양옆에 실제 건물 정면이 늘어서고, 중앙 골목을 걸어다님.
한쪽 끝 게이트 너머로 폐도시가 보여서 "안전한 안쪽 vs 위험한 바깥"의 시각적 긴장감 유지.
시설은 **슬롯 방식** — 초기엔 플레이어집 + 전당포만, 진행에 따라 빈 슬롯 건물이 셔터 열림/간판 점등으로 해금.

**건물 진입 방식 (2026-06-02 확정):**
- **실내 진입(문 → 씬 전환)**: 컨테이너 은신처, 전당포, 수리점 — 자주 쓰고 비중 큰 3곳만 내부 맵 구현
- **정면 상호작용(실내 없음)**: 블랙마켓, 의료소, 가구점, 빈 슬롯, 게시판, 지도판 — 골목에서 정면 다가가 E키 → UI 팝업
- 근거: 실내 전체 구현은 작업량 과다. 핵심 3곳만 몰입 주고 나머진 정면 처리로 절충.

### 카메라 시점 (2026-06-02 변경)

**질문**: 안전가옥 맵 시점을 3D 틸트 아이소메트릭(2:1, 26.57°)으로 갈 것인가, 2D 직교 + 아트 베이크 원근으로 갈 것인가?

**결정**: **2D 직교 카메라 + near-overhead(~80°) 원근을 아트에 베이크.**
- 거의 위에서 내려다보되 살짝 기울인 시점 (레퍼: D&D 배틀맵/프로젝트 좀보이드풍 평면도)
- 90°(완전 직하)는 아니고 70~80° — 벽/오브젝트의 윗면 위주 + 정면이 약간만 보임
- 바닥은 정사각형 그리드가 거의 정사각형으로 보임 (아이소 다이아몬드 X)
- 벽/펜스는 얇게 + 약간의 높이감만 표현

**근거/메모**: 아이소메트릭은 오브젝트 겹침/깊이정렬 복잡, 탑다운이 넓은 공터 가독성·배치 직관성 우위. 기존 탑다운 이동/조명 시스템과도 정합.

**구현 방식 확정 (2026-06-02)**:
- 카메라 = **2D 직교(orthographic) 평면 뷰** — 3D 틸트 카메라가 아님
- **틸트(80°)는 아트 자체에 미리 그려넣음** — 모든 스프라이트/타일이 80° 눕힌 시점으로 그려진 baked-in perspective
- 맵 = **타일 조립식** — 바닥 타일을 격자로 깔고, 그 위에 펜스/프랍 스프라이트 배치
- 따라서 **바닥도 90° 직하가 아니라 80° 틸트로 통일** (전체 아트 일관성). 80° = 거의 위에서 보되 살짝 눕혀 정면이 조금 보임
- 모든 에셋(바닥/벽/펜스/프랍/캐릭터)이 같은 80° 시점으로 그려져야 자연스럽게 합쳐짐

### # 격자 골목 + 실내 별도 씬 맵 구조 (위에서 본 그리드)

골목이 **#자(가로 2 + 세로 2)로 교차**하는 3×3 = 9칸 격자. 격자선 = 골목(통로).
전당포 = **내부 보이는 방**(벽 4면 + 문틈 + NPC, 지붕 없음). 집/은신처 = **컨테이너 외관 + 입구**(들어가면 **타르코프식 별도 실내 씬**=`Hideout.unity`로 전환). ▦=내부 보임, →실내=입구(씬 전환), 🔒=잠금(벽+셔터), ▓▓=세로 방호벽(게이트).

```
 ┌────────┬──────────┬──────────┐
 │ 수리점🔒 │ 전당포 ▦   │ 의료소🔒   │  상단: 전당포=중앙(내부 방+주인장 강무진+카운터)
 │ (벽)    │ [강무진]   │ (벽)      │
 ├──[셔터]─┼──────────┼──[셔터]──┤
 │ 가구점🔒 │  광장      │ 게시판 ═►게이트│  중단: 광장(허브,raid_return 스폰)
 │ (벽)    │ [raid스폰] │  회수꾼  →폐도시│       우=게시판+회수꾼+게이트(지도판 우측)
 ├──[셔터]─┼──────────┼──────────┤
 │ 블랙마켓 │ 떠돌이상인  │ 컨테이너 지역   │  하단: 중=떠돌이상인(옛 집자리)
 │ (벽)    │ (옛 집자리) │ 관리인+집[입구→실내]│   우=관리인 + 집(입구→Hideout 씬) + default 스폰
 └────────┴──────────┴──────────┘
   격자선 = # 골목(세로2·가로2)
```

- 🏠 **집/은신처**(우하 컨테이너 지역) = **컨테이너 외관(솔리드) + 입구 BuildingEntrance 트리거(→Hideout)**. 입구를 밟으면 **타르코프식 별도 실내 씬**(`Hideout.unity`)으로 자동 전환 — 침대·창고·작업대·의료대·조리대는 그 안. 같은 구역에 **구역 관리인**(집 배정, S-010) + **집 앞 default 스폰**(은신처에서 UI 나가기로 나오면 여기로 복귀). [→ '건물 전환 모델' · '실내 맵(별도 씬)' 섹션]
- **전당포**(상단 중앙) = **건물 외관(솔리드) + 입구 BuildingEntrance 트리거(→Pawnshop.unity)**. 입구를 밟으면 별도 실내 씬으로 전환(캐릭터 유지·일반 실내), **강무진(주인장)** + 카운터는 `Pawnshop.unity` 안에 상주(매매·퀘스트). 복귀 스폰=from_pawnshop(건물 앞).
- **광장**(중앙) = 열린 허브 + **raid_return 스폰**(레이드 귀환). **떠돌이 상인**(중하, 옛 집자리).
- **우측 = 출발**: 게시판(의뢰) + 회수꾼 + **동쪽 방호벽 게이트(개구부 = 게시판 바로 우측)** → 폐도시.
- **잠금 건물 4**(수리점/의료소/가구점/블랙마켓) = 솔리드 벽 + 입구 셔터('나머진 다 벽'), 해금 시 셔터 제거.
- 스폰 2: **집 앞**(default, 최초 시작 + 은신처 귀환) / **중앙 광장**(raid_return, 레이드 귀환).
- 그레이박스 좌표: 38(W)×27(H), 세로골목 X9~12·X22~25, 가로골목 Y9~12·Y17~20 (`SafehouseGreyboxLayout.cs`). 집 입구→`Hideout.unity`(`HideoutGreyboxLayout`).

### 실내 맵 (3종 별도 씬)

핵심 3곳만 내부 맵을 별도 씬으로 구현:
- **컨테이너 은신처**: 박스 침상(수면·저장) + **기능 시설 슬롯**
  > **침대 수면 UI 〔미결 · 선행 의존성〕 (2026-06-17)**: 목표 = 침대 클릭 시 **수면 시간 선택 + 시간경과 + HP/스태미너 회복 + 수분/포만감(밥) 차감**을 한 화면에 표시. **차감 표시는 허기·수분(포만감) 스탯 시스템이 선행되어야 가능** — 현재 게임에 해당 스탯 시스템이 없음(`ItemUseEffect.Food`만 '향후'로 존재). 허기/수분 시스템 범위는 **사용자 확인 대기(검토 중)**, 구체 수치·구현은 보류. (옛 S-011 기록의 "수면=허기/수분 각 -25 → survival.md"는 survival.md 미생성·시스템 부재로 **미구현 가안**일 뿐 확정 아님.)(부서진 작업대 1 + 빈 슬롯 — 타르코프 Hideout식 해금 위치; 작업대 수리→제작, 빈 슬롯엔 조리대·의료대 등 추후) — 홈 베이스(골판 금속 컨테이너 내부). **창고/장비는 Tab 전체화면 UI(별도, 컨테이너 내 물리 오브젝트 아님 → inventory.md).** 첫 귀가·정리·수면 튜토리얼 = S-011.
  - **상호작용 = 타르코프식 '화면'(걸어다니지 않음).** `HideoutController`(Hideout.unity)가 ① 플레이어 캐릭터 숨김(이동 잠금 + 스프라이트/라이트 끔) ② 카메라를 방에 고정(중심 7,4.5 / size 5) ③ **시설을 마우스 클릭 → 그 시설 단일 패널**(`HideoutUI.Show(module)`) — 미건설=건설 UI, 건설됨=업그레이드 + 기능 버튼(작업대·의료대·조리대=제작 / 창고=열기 / 라디오·파견 / 침대=휴식). 별도 "시설 관리" 버튼 없음(2026-06-17 5차). ④ 화면 '나가기' 버튼 또는 **ESC** → 아래 [ESC 2단계 규칙](#esc-동작--ui-닫기--나가기-확인창-2단계-2026-06-17)에 따라 처리(즉시 나가지 않음). 걷기+E 진입(`InteractionSystem`)은 은신처 동안 비활성. 씬 언로드 시 캐릭터·카메라 원상복구.

  - #### ESC 동작 = UI 닫기 → 나가기 확인창 (2단계) (2026-06-17)
    하이드아웃에서 ESC는 **즉시 안전구역으로 나가지 않는다.** 2단계로 동작:
    1. **열린 UI가 있으면** → 그 UI만 닫는다(하이드아웃 화면은 그대로 유지). 인벤토리/창고·`CraftingUI`·모듈 관리 등.
    2. **열린 UI가 없을 때** ESC를 누르면 → **"안전구역으로 나가시겠습니까?" 확인창**(나가기 / 취소). '나가기'를 골라야만 `SceneTransitionManager.TransitionTo("Safehouse","default")`로 집 문 앞 복귀. 화면 좌하단 **'나가기' 버튼**도 같은 확인창을 경유한다.
    - **구현**: `HideoutController` 실행 순서를 **-60**으로 두어 `UIManager`(-50)보다 먼저 ESC를 받는다. 하이드아웃 동안은 `HideoutController.IsActive`로 `UIManager`의 ESC=PauseMenu를 양보(중복 처리 방지).
    - **근거**: 실수로 레이드 거점(하이드아웃)을 나가는 사고 방지. **"UI 닫기"와 "화면 나가기"를 분리** — 인벤을 닫으려고 ESC를 눌렀는데 거점을 나가버리던 문제 해결.
  - **⚠️ 캐릭터가 안 보이는 것은 의도된 설계(2026-06-17 재확인).** 하이드아웃은 "걷지 않고 시설을 클릭하는 화면"이므로 플레이어 스프라이트/라이트를 끄고 방을 전용 카메라로 고정 프레이밍하는 것이 **정상 동작**(타르코프식). 버그가 아님. — 단, 전용 카메라 렌더 자체가 가끔 안 나오는 이슈는 **별도 조사 중(미해결)**: 캐릭터 숨김=정상이나 카메라 버그 자체는 남아 있음.
- **전당포**: 카운터 + NPC + 매매 UI. **실내 크기 5×4 타일 (5m×4m, 1타일=64px → 320×256px 그리드)** → 그레이박스는 `Pawnshop.unity`(아담한 방 + 강무진 + 카운터 + 출구 트리거).
- **수리점**: 작업대 + 도구벽 + 수리 NPC

### 건물 전환 모델 (2026-06-18, 트리거 자동 진입/퇴장)

건물 진입/퇴장 = **`BuildingEntrance` 트리거**(걸어 들어가면 자동 전환, E키 상호작용 아님). [`combat`/`상호작용` 무관, 순수 이동 트리거]

- **컴포넌트**(`Assets/Scripts/Interaction/BuildingEntrance.cs`): `Collider2D(isTrigger)` 필요. 필드 `targetScene` / `spawnPointId` / `isExit`. `OnTriggerEnter2D`에서 플레이어(Tag "Player") 감지 시 `SceneTransitionManager.Instance.TransitionTo(targetScene, spawnPointId)` 호출(페이드+additive, **캐릭터·Systems 유지**). 중복 발동 방지(`_fired` 플래그, 트리거 이탈 시 해제).
- **세이브 체크포인트**: 진입 시 `SaveCheckpoints.Instance?.BuildingEntered()`, 퇴장 시 `.BuildingExited()`(없을 수 있어 `?.` 가드).
- **진입·퇴장 둘 다 트리거**(둘 다 같은 컴포넌트, `isExit`로만 구분). 실내 씬엔 출구 트리거를 둬서 밟으면 안전가옥 건물 앞 스폰으로 복귀.
- **재진입 루프 방지**: 복귀 스폰은 반드시 입구/출구 트리거 **밖**에 배치(안에 두면 복귀 즉시 재전환).
- **건물별**:
  - **전당포**: 안전가옥 `Pawn_Entrance`(트리거→`Pawnshop`/default) → `Pawnshop.unity`의 `Exit_ToSafehouse`(트리거→`Safehouse`/from_pawnshop). **캐릭터 있음**(일반 실내, 걸어다님). 강무진은 Pawnshop.unity 안.
  - **집/은신처**: 안전가옥 `Hideout_Entrance`(트리거→`Hideout`/default)로 진입. **퇴장은 트리거 없음** — 하이드아웃은 캐릭터 없는 클릭 화면이라 걸어나갈 수 없음 → `HideoutController`의 UI '나가기'/ESC가 `Safehouse`/default로 복귀. (`Hideout.unity`의 옛 `Exit_ToSafehouse` 걷기 출구는 제거.)
- **기존 `InteractableObject.ExitPoint`(E키 전환)는 그대로 둠** — 레이드 탈출 등 다른 용도. 건물 입구만 BuildingEntrance로 교체.

- 게이트 너머: 폐도시로 이어지는 도로

### 스토리 동선 (S-001 ~ S-007)

프롤로그 플레이어 동선 (첫 진입 시 NPC 에스코트):
```
골목 기상(S-000) → 불빛 향해 이동(S-001) → 전당포 A1 도착(S-002)
→ 대화·제안(S-003) → 주인이 에스코트: A1→A2 컨테이너(S-004)
→ 컨테이너 내부 소개 (침대/보관함/고장 작업대)
→ 바깥 나와 빈 공터 가리킴 ("의료소라든가, 수리점이라든가")
→ 게이트+게시판+지도판 가리킴
→ 카운터 복귀, 아이템 지급 (녹슨 파이프, 붕대 x2)
→ 컨테이너 복귀·휴식(S-005) → 지도판(S-006) → 게이트 출전(S-007)
```

**배치 원칙 (스토리 근거)**:
- A1(전당포)과 A2(컨테이너)는 **물리적으로 인접** — "전당포 천막 뒤쪽"
- 게이트는 전당포/컨테이너에서 **건너편** — "공터 끝쪽"
- 빈 슬롯들은 에스코트 중 **한 눈에 보이는 개방 공터**
- 첫 진입(골목→전당포)은 프롤로그 전용 컷신, 이후 귀환 시 안전가옥 씬 직접 로드

### 하이드아웃 UI = 시설 아이콘 뷰 → 우측 업글/제작 패널 (2026-06-17, 타르코프 참조)

**개념**: 하이드아웃(안전구역) 시설 관리 UI = **시설 아이콘이 배치된 뷰 화면**. 타르코프 하이드아웃처럼 "뷰에서 시설 아이콘 선택 → 우측에 상세 패널".

- **뷰(좌/중앙)**: 각 시설(작업대·발전기·창고·의료대·취사대·라디오·파견 등)이 **아이콘**으로 배치되어 보임. 아이콘은 현재 Lv·잠금/해금 상태를 표시.
- **클릭 → 우측 패널**: 시설 아이콘을 클릭하면 **우측에 패널**이 떠서 그 시설의 **업그레이드(Lv업)** 또는 **제작** 창을 띄움.
  - **업글 패널**: 다음 Lv에 필요한 **재료·스크랩 비용**(모듈×Lv 비용 = `tools/balance/hideout_modules.csv` / §9.7 ③ Lv별 비용표) + **현재 Lv → 다음 Lv 효과**.
  - **제작 패널**: 그 시설에서 만들 수 있는 **레시피 목록**(작업대=무기·도구, 의료대=일회용 치료템, 취사대=버프 음식 등 → [`crafting.md`](crafting.md)).
- 모듈 데이터/해금 게이팅(신뢰도·평판·NQ-M 도면)은 [`quests-region1.md`](quests-region1.md) §9.7 ③ 관리인 하이드아웃 모듈 트리와 동일. 이 UI는 그 트리를 **시각적 시설 뷰 + 우측 상세**로 표현하는 표현 계층.

**진입 경로 = 하이드아웃 내부에서만 (2026-06-17 확정)**: 모듈 업그레이드 UI(`HideoutUI`)는 **전역 단축키(H)로 열지 않는다.** 하이드아웃 실내(`HideoutController`) 화면의 **'시설 관리(업그레이드)' 버튼**으로만 진입한다. 즉 거점 안에 있을 때만 접근 가능 — 안전구역 어디서나 부르는 메뉴가 아님.
> **발전 방향**: 추후 시설 **아이콘을 직접 클릭하면 그 시설 패널만 뜨는** 방식(참조 이미지처럼 시설별 개별 호출)으로 확장 예정. 현재는 '시설 관리' 버튼 1개로 모듈 관리 화면 전체를 연다.

**핵심 원칙**: **"한 화면에 모든 UI가 다 떠있는 느낌이 아니라, 실제로 눌러서 해당 UI만 나오는 느낌."** 즉 각 패널은 **트리거(NPC/시설/탭/버튼)로 개별 호출되는 모달** — 6패널이 한꺼번에 떠 있는 대시보드가 아니다. (위 [하이드아웃 UI](#하이드아웃-ui--시설-아이콘-뷰--우측-업글제작-패널-2026-06-17-타르코프-참조) 의 "아이콘 클릭 → 그 시설 패널만" 발전 방향과 동일 철학.)

> 인벤토리/창고 패널의 레이아웃 상세(좌 장비창+가방 / 우 창고)는 [`inventory.md`](inventory.md) §UI 레이아웃. 03 보관함의 "창고 레벨 N" = 하이드아웃 stash 모듈 레벨에 비례한 칸 확장(아래 [메인 창고](#메인-창고--안전구역-tab-우측-상시-표시-2026-06-17) 참조).

## 메인 창고 — 안전구역 Tab 우측 상시 표시 (2026-06-17)

**결정**: 안전구역(안전가옥/하이드아웃)에서 인벤토리(Tab)를 열면 **우측 열에 메인 창고가 항상 보여야 한다**(우측이 비면 안 됨). 반대로 **레이드 중에는 우측이 비어 있다가**, 상자에 다가가 **E로 수색**할 때만 그 상자의 파밍 칸이 우측에 채워진다.

- **구현**: 영속 **'메인 창고(`MainStash`)'** 도입. 어떤 그레이박스 씬에도 창고 가구가 없어 안전구역에서도 우측이 늘 비던 문제를 해결.

## 창고 시스템 (가구 기반)

> ⚠️ **폐기·대체(2026-06-10)**: 아래 `FurnitureData`(물리 가구) 스키마는 **옛 방식**. 현 구현 = **보관함 = ItemData + 컨테이너 필드**(타르코프 케이스, 루팅·판매 가능) → 진실은 [`inventory.md`](inventory.md) §보관함 데이터 구조. 아래는 카테고리·격자 발상 참고용으로만 보존.

### 핵심 개념

창고 = **카테고리별 전용 가구**. 낙원처럼 NPC에게 가구를 구매하여 안전가옥에 배치.

### 가구 종류

**SO 경로**: `Assets/Resources/Data/Furniture/` — `Tools > Dev Tools > Data > Generate Default Furniture` 로 재생성 가능.

**Interactable Creator 프리셋** (창고 + `SafehouseStorage` + FurnitureData 자동 연결):

### 규칙

- **카테고리 제한**: 전용 가구에 안 맞는 카테고리 아이템은 **배치 불가**
- **범용 상자**: 카테고리 제한 없음 (아무거나 보관 가능)
- **복수 보유**: 같은 가구를 여러 개 구매 가능 (냉장고 2대, 상자 3개 등)
- **NPC 구매**: 안전가옥 NPC에게 스크랩 + 재료로 구매
- **물리 배치**: 구매한 가구는 안전가옥 공간에 오브젝트로 배치됨

### 데이터 구조 (설계안)

```
FurnitureData (ScriptableObject)
├── furnitureId     : string ("box_basic", "fridge", "weapon_rack" 등)
├── displayName     : string ("일반 상자", "냉장고")
├── gridWidth       : int (격자 가로)
├── gridHeight      : int (격자 세로)
├── allowedCategories : ItemCategory[] (허용 카테고리, 빈 배열=전체 허용)
├── buyPriceRudy    : int (루디 가격)
├── buyMaterials    : MaterialCost[] (필요 재료)
├── sprite          : Sprite (가구 스프라이트)
└── description     : string
```

```
SafehouseStorage (리팩터링 필요)
├── ownedFurniture  : List<FurnitureInstance> (보유 가구 목록)
│   ├── data        : FurnitureData
│   ├── grid        : InventoryGrid (각 가구별 독립 격자)
│   └── position    : Vector3 (안전가옥 내 배치 위치)
```

### 구매 흐름

1. 안전가옥 NPC에게 말을 건다
2. 가구 상점 UI → 구매할 가구 선택
3. 스크랩 + 재료 확인 → 구매
4. 안전가옥에 가구 오브젝트 자동 배치 (또는 플레이어가 위치 선택)
5. 이후 해당 가구에 다가가서 상호작용 → 전용 격자 열림

## 제작 시스템

**레시피 SO · 에디터 절차**: [`crafting.md`](crafting.md) — `Assets/Resources/Data/Recipes/` → Create → Dev Tools → Item → Recipe Data.

**제작 UI (구현됨)**: `MedicalBench` / `CookingBench` / `Workbench` 타입 `InteractableObject`에 **E** → `CraftingUI`. 씬·Creator로 직접 배치.

### 의료대 — 일회용 치료템 전용

- **제작 가능**: 일회용(스택) 치료템만 (붕대, 부목, 거즈, 진통 패치 등)
- **제작 불가 / NPC 구매**: 고급 치료템 (구급상자, 봉합 키트, 수술 키트, 모르핀 등)
- 레이드에서 파밍한 재료(`cloth_rag`, `chemical_flask` 등)로 제작
- 의료대 레벨업 → 제작 가능 종류 확장

### 조리대 — 음식 재료 → 버프 음식

- 레이드에서 **음식 재료** (식재료 아이템)를 가져와 조리
- 조리 결과물은 **이로운 버프** 부여:
  - 피로도 회복량 증가
  - 수분 회복량 증가
  - 일정 시간 체력 재생
  - 스태미나 회복 속도 증가 등
- **레시피**: 맵에서 레시피 아이템을 루팅하여 해금 (새 아이템 카테고리 추가)
- 조리대 레벨업 → 고급 레시피 해금, 버프 효과 강화
- 낙원 참고: 기본 음식 대비 조리 음식이 확실히 나은 보상

### 작업대 — 레시피 해금 + 수리

**레벨 없음, 레시피 해금 방식** (조리대와 동일 패턴)
- 작업대 자체에 레벨 개념 없음
- 맵에서 **무기/도구 제작 레시피**를 루팅하거나 NPC에게 구매하여 해금
- 해금된 레시피 + 재료 → 제작
- 작업대 업그레이드(설치 개선)가 필요한 경우: **스크랩 + 재료** (타르코프식 비용)

**수리 시스템**
- **재료 소모형**: 수리할 때마다 재료(고철, 천 등) 소비
- 내구도 완전 회복이 아닌 **일부 회복** (예: 1회 수리 = +30%)
- 수리 재료는 무기 종류에 따라 다름 (금속 무기 → 고철, 가죽/천 계열 → 천 조각 등)

**내구도 0 처리: 사용 불가 (파괴 아님)**
- 내구도 0 → 장착/공격 불가, 인벤에 남아있음
- 작업대에서 수리하면 부활
- 좋은 무기를 잃는 억울함 방지, 수리 동기 유지

### 루디 충전/가공대 — 부분 충전 + 가공 〔확정 방향 · 수치 TBD〕

거점에서 방전·죽은 루디를 다시 머금게 하는 시설(현상 노드 대비 **느리지만 안전**). [→ gdd-core §5.3](gdd-core.md), [crafting.md](crafting.md)
- **충전**: 방전 루디 → 부분 회복(전부는 아님). 안전가옥 강화로 해금/효율↑.
- **가공**: 소형 루디를 갈아 큰 루디 소폭 보충, 또는 **안정화**(반복 충전 마모를 늦추는 강화).
- 충전 속도·효율·마모 지연율 = `GameTuning` TBD. **확인 필요**: 별도 스테이션 SO로 둘지 작업대 탭으로 통합할지 = 구현 판단 대기.
