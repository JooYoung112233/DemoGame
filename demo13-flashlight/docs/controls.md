# 컨트롤 / 입력 매핑

> 키보드·마우스 + **게임패드** 입력 매핑의 단일 출처.
> 입력 아키텍처(신 Input System + `GameInput` 셰임)는 [`architecture.md`](architecture.md) §입력 시스템 참조.

---

## 입력 아키텍처 요약

- 프로젝트는 **신 Input System 전용**(`activeInputHandler:1`). `UnityEngine.Input.*` 직접 호출 금지.
- 모든 게임플레이 입력은 `Scripts/Core/GameInput.cs` **정적 폴링 셰임**을 경유한다.
- 게임패드는 **셰임 확장 방식**으로 지원 — 별도 `.inputactions` 에셋·액션맵 없이, `GameInput`이 `Gamepad.current`를 읽어 기존 키보드/마우스 조회에 **병합**한다. 호출처(95곳) 무변경.
- UI 내비게이션은 `EventSystem`의 `InputSystemUIInputModule + AssignDefaultActions()`로 **패드 기본 내비게이션(스틱/D패드 이동, A=확인, B=취소)이 기본 동작**한다.

## 디바이스 전환 (조준 소스)

- `GameInput.Tick()`을 매 프레임 `TopDownPlayer.Update()` 첫머리에서 호출 → 마지막 사용 디바이스를 추적(`GameInput.PadActive`).
- **오른쪽 스틱·왼쪽 스틱·패드 버튼**을 쓰면 `PadActive=true` → 조준이 오른쪽 스틱 기준(마우스 커서 무시).
- **마우스를 물리적으로 움직이거나 클릭**하면 `PadActive=false` → 마우스 커서 조준 복귀.
- 덕분에 키보드+마우스 ↔ 패드를 즉시 매끄럽게 혼용 가능.
- 패드 페이싱 우선순위: **오른쪽 스틱 > 이동 방향(왼쪽 스틱) > 마지막 방향 유지.** 오른쪽 스틱을 안 써도 걸어가는 방향을 바라봐 facing이 고착되지 않는다.
- 트리거→마우스 클릭 병합은 **UI 열림 중 억제**(`GamepadForMouse`) — 인벤토리를 열어둔 채 트리거를 당겨도 격자 유령 드롭/분할이 안 난다.

## 알려진 한계 / 남은 단계

현재 구현 범위 = **T0(입력 기반) + T1(레이드 조작)**. 아래는 후속.

- **T2 (메뉴 UX)** — 미구현:
  - 여러 패널이 선택 하이라이트 깜빡임 방지로 `SetSelectedGameObject(null)` → 패드 포커스와 충돌. 패널 열 때 `firstSelected` 지정 필요.
  - 리스트 휠 스크롤이 EventSystem 비의존 직접 폴링(마우스 휠) → **패드로 리스트 스크롤 불가**. 스틱→스크롤 배선 필요.
  - UI '취소(B)'는 모듈 레벨 Cancel 이벤트지만, 대부분 패널은 `GameInput.GetKeyDown(Escape)` 폴링으로 닫음 → **현재 패드 닫기는 Start로 통일**. B 닫기는 T2에서 배선.
  - 버튼 프롬프트 글리프(A/B/X/Y 아이콘) 미표시.
- **T3 (격자 인벤토리)** — 미구현: 인벤토리 드래그·이동·분할이 전부 마우스 위치 기반(`GridDragManager`/`GridDragView`). 패드용 **스틱 격자 커서** 신설 필요(최대 비용).
- 진동/햅틱, 감도·데드존 사용자 설정, 키 리매핑 UI: 미정.

## 변경 로그

| 날짜 | 내용 |
|------|------|
| 2026-09-11 | **이동 = 화면 기준** — 카메라가 대각선 쿼터뷰(방위 45°)가 되며(docs/rendering.md §쿼터뷰 카메라) W = 화면 위, D = 화면 오른쪽. 키보드·왼쪽 스틱·오른쪽 스틱 조준 모두 `TopDownPlayer.CameraRelative`. 월드 방향을 가상 입력으로 넣는 QA 봇은 역변환 `WorldToInput`을 거친다. |
| 2026-09-11 | **바라보는 방향 변경** — 사용자: "움직임이 지금 마우스를 무조건 따라가는데, 조준 상태에서만 마우스 쪽을 보고 일반적으론 키보드 움직임 방향을 바라보자". 평소 = 이동 방향(멈추면 마지막 방향), 총 조준(우클릭) 중 = 커서 쪽. 조준원도 조준 중에만. 조준 없이 쏜 총·근접 공격은 바라보는 방향으로 나간다. 패드는 기존 그대로(오른쪽 스틱 > 이동 방향). `TopDownPlayer.UpdateMouseFacing` · `AimReticle`. |
| 2026-07-09 | **문서 신설 + 게임패드 지원 T0/T1 구현.** 결정: 입력 기반 = **GameInput 셰임 확장**(신규 액션 에셋 대신 `Gamepad.current` 병합), 범위 = **레이드 조작(T1)까지**. `GameInput`에 왼쪽 스틱 이동(GetAxisRaw 병합)·오른쪽 스틱 조준(`AimStick`/`PadActive`/`Tick`)·`KeyCode`→패드 버튼 맵(E→A/Space→B/Shift→L3/C→Y/Esc→Start/Tab→Select/1~4→D패드)·마우스 버튼→트리거(0→RT/1→LT) 추가. `TopDownPlayer.Update`가 매 프레임 `Tick()` 호출 + `UpdateMouseFacing`에 패드 분기(오른쪽 스틱 페이싱). UI 기본 내비는 기존 `InputSystemUIInputModule` 그대로. T2(메뉴 포커스/스크롤/글리프)·T3(격자 인벤 스틱 커서)은 후속. |
