# 적 AI — 지각 + 행동 학습

> **목표: 적을 "똑똑하고 무섭게".** 두 축 — ① **지각**(소음 듣고 조사·시야콘·수색) ② **학습**(플레이어 행동 프로파일 → 적 변수 조절).
> 지각·전투 수치의 단일 색인은 [`balance.md`](balance.md)(GameTuning). 근접 전투 메커닉은 [`combat.md`](combat.md).

---

## 1. 현재 상태 (2026-07-10 기준)

### 이미 구현됨 — 지각 오버홀 (별도 세션, 이 문서 작성 시점엔 미커밋 작업 트리)
- **`NoiseSystem`**(정적 청각 허브) — 플레이어 지속(이동) 소음 + 순간 펄스(타격·문)를 등록, 적이 `TryHear(pos, out src)`로 질의. `PlayerNoise`가 매 프레임 반경 갱신.
- **`EnemyController` Investigate 상태** — `TryHear` → `EnterInvestigate(src)` → 소음 지점 이동 → `noiseInvestigateLook`(GameTuning) 초 두리번 → 순찰 복귀.
- **FOV 시야콘**(`PlayerVision`, GameTuning `visionFovDegrees/Range/NearRadius/LineOfSight`) — 좀보이드식.
- **`EnemySpawner`** — `SpawnZone.enemyCount × GameTuning.enemySpawnCountMult` 스폰(과거 "소비처 없음" 해소됨).
- GameTuning 노브: `noiseIdle/Crouch/Walk/Run/Attack/Door`, `noisePulseDuration`, `noiseInvestigateLook`, `visionEnabled/FovDegrees/Range/NearRadius/LineOfSight`.

> ⚠️ 위 지각 작업은 **병렬 세션 소유**. 학습 레이어는 그 위에 **얹기만** 하고 `EnemyController`/`NoiseSystem`/`GameTuning`을 재작성하지 않는다(중복·충돌 금지).

### 길찾기 — 2026-07-27 실제로 켜짐

`NavGrid`(격자) + `NavAgent`(A* 추종) + `AStarPathfinder`는 예전부터 있었지만
**`NavGrid`를 CombatSandbox 씬에서만 생성**해서, 실제 게임 씬 18개
(Safehouse/Zone1/Int_\*12/Pawnshop/Hideout…)에는 격자가 하나도 없었다.
`NavAgent.Repath`는 격자가 없으면 경로를 버리고 **목표 직진 폴백**하므로
→ **적은 추격·조사 내내 직선으로만 움직였고 벽에 비볐다.**

QA 자동 플레이가 STUCK 8회 + `UNREACHABLE`로 잡아냈다(봇도 같은 `NavAgent`를 쓴다).

**조치**: `NavGridBootstrap`(신규)이 씬 로드마다 격자를 자동으로 깐다.
- 씬 콜라이더 전체를 감싸는 영역을 자동 계산(여유 4m), 한 변 220셀을 넘으면 셀을 키워 베이크 비용 상한
- 손으로 배치한 `NavGrid`가 있으면 그쪽을 존중하고 건너뜀 / `Systems` 씬·맵툴 씬은 제외
- 씬과 함께 소멸 → 맵을 옮기면 새 격자가 깔림. 런타임 지오메트리 변화는 `NavGridBootstrap.Rebake()`
- 콘솔에 `[NavGrid] 자동 배치 — <씬> 영역 …  막힘 x%` 로그. **막힘 0%면 경고** (베이크 시점 의심)

> 이 격자는 적뿐 아니라 **NPC 이동**과 **QA 봇**이 공유한다.

### 아직 없음 — 학습 레이어 (이 문서의 대상)
- 플레이어 행동 프로파일, 아키타입 분류, 프로파일→적 변수 적용.

## 2. 설계 — 행동 "학습" (실 ML 아님, 지표 집계)

### 2.1 `PlayerBehaviorProfile` (신규 매니저, 예정)
레이드 중 플레이어 행동 지표를 집계 → 아키타입 분류 → **세이브 누적**(EMA로 최근 가중).

| 지표 | 집계 소스(예) |
|------|--------------|
| 잠행 비율 | 앉기 시간 / 총 시간, 적 시야 밖·미탐지 유지 시간 |
| 교전 성향 | 처치 수 vs 회피(감지 후 이탈) 수, 평균 교전 거리(근접 러시 vs 카이팅) |
| 루팅 집중 | 상자 수색 수 / 시간, 전투 회피율 |
| 소음 습관 | 달리기·타격 소음 발생 빈도(NoiseSystem 활용) |

### 2.2 아키타입 (분류 결과)
| 아키타입 | 성향 | 
|---|---|
| **유령(Ghost)** | 잠행·미탐지 위주, 전투 회피 |
| **스캐빈저(Scavenger)** | 전투 피하며 루팅 극대화 |
| **헌터(Hunter)** | 적극 교전·처치 |
| **러너(Runner)** | 교전·루팅 최소, 탈출 지향 |

### 2.3 지속성 = 세이브 누적 (사용자 결정 2026-07-10)
- 레이드를 거듭할수록 프로파일이 쌓임 → 적이 "당신을 기억"해 점점 맞춤형·무서워짐(로그라이크식 긴장).
- **EMA**(지수이동평균)로 최근 플레이 변화도 반영(스타일 바꾸면 서서히 따라옴).
- 저장: `SaveManager` 확장(프로파일 지표/아키타입 직렬화).

### 2.4 적용 매핑 (프로파일 → 적 변수) — **지각 커밋 후 배선**
GameTuning 노브를 통해 아키타입별로 조절(값 곱/가산):
| 아키타입 | 적 변화(예) |
|---|---|
| 유령/스캐빈저 | 청각 예민도 ↑, `noiseInvestigateLook` ↑(오래 수색), 은신처 확인 경향, 스폰 시 매복형 배치 |
| 헌터 | 전투 시 견제·플랭크·페인트, 더 공격적 추격 |
| 러너 | 탈출로 차단 경향, 추격 지속 ↑ |

> 적용은 **개체별 지각/전투 튜닝**(항상 동작)을 우선. 스폰 구성 조절은 `EnemySpawner`가 프로파일을 읽게 배선.

## 3. 단계 계획 (protocol: 한 슬라이스씩 열고 닫기)

1. **[다음] 학습 토대** — `PlayerBehaviorProfile` 신규 파일: 지표 집계 + 아키타입 분류 + 세이브 누적(EMA) + **F키 디버그 리드아웃**. `EnemyController` 안 건드림(충돌 0).
2. **적용(지각)** — 병렬 세션의 지각 커밋이 올라온 뒤, 프로파일 → 청각 예민도·수색 시간·스폰 배치 배선.
3. **적용(전투)** — 아키타입별 전투 차이(견제·플랭크·페인트).
4. **밸런스** — 아키타입 임계값·적용 강도를 GameTuning으로 노브화 + [`balance.md`](balance.md) 색인.

| 2026-09-09 | 플레이어가 적을 밀어버린다 — 어떻게 막나? | **적 질량 1 → 300.** 기본값 1로 남아 있어 플레이어(70)가 스치기만 해도 날아갔고, 구르기(3m/0.3s=10m/s)로 파고들면 볼링처럼 밀려났다. 적의 이동은 `SetVelocity`로 속도를 직접 넣으므로 **질량을 키워도 발걸음은 그대로**고 충돌 반응만 단단해진다 → 적이 **길을 막는** 압박이 성립한다(사용자 요구: 길막 가능). 넉백 연출은 별도 경로라 영향 없음. |
