# NPC 호감도 & 대화 시스템

## 시스템 개요
NPC와의 관계를 3축 호감도로 관리하고, 혼합형 대화 시스템으로 스토리를 전달한다.

> **관계 엔진 = 여기(3축: 호감/신뢰/두려움)가 진실.** retention 문서 [`quests-region1.md`](quests-region1.md) §9는 플레이어 미터기를 **"신뢰도(대표 관계축)"** 한 단어로 표기하지만, 이는 엔진의 대표 표기(주로 Trust)일 뿐 — 거래상=호감, 깊은 관계=신뢰, 위협=두려움의 **3축은 그대로 유지**(2026-06-10 확정). 호감 축 삭제 아님.

---

## 1. 호감도 시스템 (3축)

### 1-1. 호감도 (Affinity)
- **정의**: NPC가 플레이어를 얼마나 좋아하는가
- **상승**: 선물 제공, 퀘스트 완료, 호의적 대화 선택지
- **하락**: 나쁜 대화 선택지 선택 시
- **효과**: 상점 품목 확장, 추가 퀘스트 해금, 엔딩 단서 제공

### 1-2. 신뢰도 (Trust)
- **정의**: NPC가 플레이어를 얼마나 믿는가
- **상승**: 약속 이행, 중요 임무 성공, 위험 상황에서 NPC 구출
- **하락**: 임무 실패, 배신 행위, 거짓말 선택지
- **효과**: 핵심 정보 공개 (밤 지역 힌트, 동생 단서), 고급 제작 레시피 해금, 시설 업그레이드 할인

### 1-3. 두려움 (Fear)
- **정의**: NPC가 플레이어를 얼마나 두려워하는가
- **상승**: 위협/강압 대화 선택지, 폭력적 행동
- **하락**: 없음 (한번 쌓인 두려움은 유지)
- **효과 (복종형)**:
  - 가격 할인, 즉각적 정보 제공
  - **대가**: 대화 톤이 차갑고 위축됨, 호감도/신뢰도 기반 콘텐츠 잠김
  - 호감도·신뢰도 루트에서만 나오는 퀘스트/엔딩 단서를 영구 차단할 수 있음

### 1-4. 축 간 관계
| 행동 | 호감도 | 신뢰도 | 두려움 |
|------|--------|--------|--------|
| 퀘스트 완료 | +2 | +3 | — |
| 선물 제공 | +3 | +1 | — |
| NPC 구출 | +2 | +5 | — |
| 약속 이행 | +1 | +3 | — |
| 임무 실패 | — | -3 | — |
| 위협 선택지 | -2 | -1 | +3 |
| 나쁜 선택지 | -2 | — | — |

> 수치는 밸런싱 단계에서 조정. 현재는 상대적 비율만 표현.

### 1-5. 서사 관계 단계 (핵심 NPC 전용)

3축(수치) 위에 얹는 **서사 레이어**. 거래·일반 대화는 3축이 담당하고, 핵심 NPC의 깊은 관계 변화(과거·죄책감 등)는 "단계"로 표현한다.

- **적용 대상**: 강무진 등 스토리 핵심 NPC만. 노점상·협상꾼 같은 일반 NPC는 단계 없이 3축만.
- **진행 조건**: `신뢰도 임계 + 진실 단서(플래그)` 둘 다 충족해야 다음 단계로. **수치만으로는 안 열림** — 스토리 단서가 게이트.
- **비가역**: 한번 오른 단계는 내려가지 않음 (드러난 진실은 안 닫힘).
- **두려움 게이트**: 두려움이 일정 이상이면 감정적 단계(고백 등)가 영구 차단.
- **효과**: 단계가 오르면 대사 톤·공개 정보·행동이 바뀐다. 플레이어가 "올리는" 게 아니라, **진실을 모아 NPC가 더는 숨기지 못하게 되는** 구조.

> 강무진의 단계 설계 → story.md §10.

## 2. 대화 시스템 (혼합형)

### 2-1. 기본 구조
- **평상시**: 상태 기반 대화 — 호감도/신뢰도/두려움 수치 + 퀘스트 진행도에 따라 NPC가 다른 대사 출력
- **중요 이벤트**: 선택지 분기 — 2~3개 선택지 팝업, 선택에 따라 호감도 변화 + 스토리 분기

### 2-2. 대화 흐름
```
[플레이어가 NPC에게 접근 → E키 상호작용]
    │
    ├─ 일반 대화 (상태 기반)
    │   └─ 조건에 맞는 대사 1~3줄 출력
    │   └─ [계속] 버튼으로 진행
    │
    └─ 이벤트 대화 (선택지 분기)
        └─ NPC 대사 출력
        └─ 선택지 2~3개 표시
        └─ 선택 → 결과 대사 + 호감도 변동 + (선택적) 퀘스트 트리거
```

### 2-3. 대화 우선순위
대화 시작 시 아래 순서로 체크:
1. **긴급 이벤트 대화** (퀘스트 완료 보고, 스토리 트리거 등)
2. **신규 퀘스트 제안** (조건 충족 시)
3. **상태 기반 일반 대화** (호감도 구간별 대사풀에서 랜덤)

## 4. 데이터 구조 (ScriptableObject)

### 4-1. NPCData (ScriptableObject)
```
NPCData
├── npcId: string
├── displayName: string
├── role: string (예: "전당포 주인", "의사")
├── initialAffinity/Trust/Fear: int       // 첫 대면 시 1회 시드 (NPCController→SeedRelationship). §5 '초기 호감도' 데이터화
├── defaultDialogues: DialogueEntry[]     // 상태 기반 기본 대사
├── eventDialogues: EventDialogue[]       // 이벤트/선택지 대화
├── shopData: ShopData (optional)         // 거래 — 선택지 openShop으로 진입
├── relationshipArc: RelationshipStage[] (optional)  // 핵심 NPC만 — 서사 관계 단계 (§1-5)
└── availableQuests: QuestData[] · shopInventory: ItemData[] (optional)
```

### 4-2. DialogueEntry
```
DialogueEntry
├── id: string
├── lines: string[]                       // 순차 출력할 대사들
├── conditions: DialogueCondition         // 출력 조건
│   ├── minAffinity: int
│   ├── minTrust: int
│   ├── minFear: int
│   ├── requiredQuest: string (완료 필수 퀘스트)
│   └── requiredFlag: string (범용 플래그)
└── priority: int                         // 같은 조건 충족 시 우선순위
```

### 4-3. EventDialogue
```
EventDialogue
├── id: string
├── triggerCondition: DialogueCondition
├── npcLines: string[]                    // NPC 대사
├── choices: DialogueChoice[]
│   ├── text: string                      // 선택지 텍스트
│   ├── affinityChange: int
│   ├── trustChange: int
│   ├── fearChange: int
│   ├── resultLines: string[]             // 선택 후 NPC 반응
│   ├── triggerQuest: string (optional)
│   ├── setFlag: string (optional)
│   └── openShop: bool                    // 이 선택지로 연결된 ShopData 열기
└── oneShot: bool                         // true면 1회만 발생
```

### 4-4. NPCRelationship (런타임 데이터, 세이브 대상)
```
NPCRelationship
├── npcId: string
├── affinity: int (0~100, 초기값 20)
├── trust: int (0~100, 초기값 10)
├── fear: int (0~100, 초기값 0)
├── completedEvents: HashSet<string>      // 이미 본 이벤트 대화
├── currentStage: int (기본 0)            // 서사 관계 단계 (핵심 NPC, §1-5)
└── flags: Dictionary<string, bool>       // 범용 플래그
```

### 4-5. RelationshipStage (서사 관계 단계, §1-5)

```
RelationshipStage
├── stage: int                            // 단계 번호 (0부터)
├── label: string                         // 단계 이름 (예: "죄책 고백")
├── unlockTrust: int                      // 진행 신뢰도 임계
├── requiredFlags: string[]               // 필요한 진실 단서 플래그 (모두 충족)
├── maxFear: int                          // 초과 시 단계 잠금 (감정 차단 게이트, 0=무관)
└── onEnterEvent: string                  // 단계 진입 시 재생할 EventDialogue id
```

## 5.5 NPC 배경·성격 프로필

> **대사 작성 시 필수 참조.** 살아 있는 NPC — 튜토리얼 NPC처럼 말하지 않는다.
>
> **성격 작성 원칙**: 형용사 나열보다 **대비·말버릇·금기**를 쓴다. NPC마다 "이 사람만의 한 가지"가 대사에서 바로 느껴져야 한다.
>
> **공통 금지 (NPC 입에서)**: 아이콘, UI, 버튼, 퀘스트, 플래그, 인벤, HUD, "시스템", 메뉴 이름.
> **대신 쓸 것**: 보이는 것·듣는 것·몸으로 겪는 것(불빛, 공기, 발소리, 글씨, 종이, 문, 골목).

| **성격** | 능글맞고 빠르다. 상대 약점을 장난으로 찌르고("목마른 건 너지") 바로 물건 꺼냄. 싫으면 **돌려보내기**가 일관됨. 위험한 곳도 돌아다니는 건 **장사가 되니까** — 용기가 아니라 계산. |
| **말버릇** | `사지 마` · `비싸지` · `발품값` · 상대 상황을 **돈으로 환산**하는 한 마디 |

### 5.6 대사 톤 가이드 — `story-script.md` S-000~S-010 (사용자 정리)

> 이후 S-011 이후·신규 대사 작성 시 **이 톤을 기본**으로 한다. 레퍼런스 = 현재 `story-script.md` CH0~S-010.

**느낌 한 줄**: 살아 있는 사람이 **할 말만** 짧게. 설명·튜토리얼·복붙 안내는 NPC 입에 넣지 않는다.

| 할 것 | 하지 말 것 |
|--------|------------|
| **한 줄 = 한 정보**(행동 지시, 거절, 한 마디 농담) | 한 문장에 두세 가지 뜻을 이어 붙이기 (`추천해주지 폐상가 쪽 이 하나있을꺼야`) |
| **말 끊기** — `……`로 숨 고르기, 다음 줄에서 이어 말하기 | 강의체·배경 설명 나열(루디·현상 5줄 연속) |
| **같은 안내 반복 금지** — 게시판·의뢰는 한 번만 | 앞에서 말한 걸 마무리·선택지에서 또 설명 |
| **구어·거침** — `가져왓어`, `니 수준`, `똥 강아지` (맞춤법 완벽보다 말투 우선) | NPC가 시스템·동기·규칙을 **풀어서** 설명 (`부모가 나갈 때 아이를 보호하기 위한 수단`) |
| 플레이어는 **존댓말·짧게** (`의뢰요?`, `……예.`) | 플레이어가 NPC처럼 세계관 브리핑 |
| 선택지 답변 **1~2문장** (필요하면 3, 그 이상은 `#veteran_intro`식 반복 질문으로 분리) | 선택지마다 4~5문장 정보 방출 |
| 안 되는 말은 **안 한다** (`말해줄 수 있는 건 여기까지`) | 끝까지 친절히 다 가르치기 |

**NPC별 호흡 (S-010 기준)**

- **전당포 주인**: 설명·위로 금지. `불씨` 던지고 쫓음. 시계·과거는 `……`로 미룸.
- **회수꾼**: 농담·짧은 명령·`다시 와`. 강의·칭찬 없음. 상자 받을 땐 **말 끊김**.
- **구역 관리인**: 장부·칸·기한만. `니 수준엔 여기뿐이야` — 친절 대신 조항.
- **떠돌이 상인**: 농담 → 바로 값 매김. `사지 마`로 문 닫기.
- **약탈꾼**: 위협 한두 줄 → 숫자. 연기처럼 크고, 실리로 끝냄.
- **생존자**: 겁에 `제발` 반복 → 구출 후 짧은 감사.

**문장 끊김 예시 (좋음)**

```
"……알았으면 가봐."
"의뢰 수령하고 나서 다시 말 걸어."
"볼 필요 없어. 난 뭐가 들었는지 아니까."
```

**TMI 예시 (피함)**

```
"의뢰 니 수준에 맞는 걸 하나 추천해주지 폐상가 쪽 이 하나있을꺼야"  ← 한 줄에 너무 많음 → 둘로 쪼개거나 하나 삭제
"....규칙이군. 부모나 보호자가 나갈때 아이를 보호하기 위한 수단중 하나이지"  ← 설명문 → "……규칙이군." 정도
```

**암구호·호칭**: 암구호 `불씨` ≠ 호칭 `새벽`. 암구호는 넘기기용, 호칭은 S-007 이후.
