### 2026-06-05 — 플레이어/맵 스케일 정합
- **질문**: 플레이어 점유 크기 2×2(2m) vs 1×1(1m)? (그레이박스/타일은 1m 단위)
- **결정**: **1×1(1m).** 그레이박스 1m 타일과 정합 → 문·통로 1m도 그대로 통과(2m 확대 불필요). 좀보이드 표준(캐릭터=1타일).
- **근거**: 2m면 캐릭터가 좀보이드의 2배라 문/통로/방을 전부 2배로 키워야 해 맵이 비대해짐. 1m로 맞추면 1m 그레이박스를 그대로 사용. 플레이어 콜라이더 0.6m가 이미 1타일 안이라 점유 1×1 충족(스프라이트만 1타일감으로 정리 여지).
- **밀도 메모(좀보이드式)**: 플레이어 1m 기준 복도 4m=4칸은 다소 넓음 → 3m로 좁히고 방도 축소해 밀도↑(전투 공간과 트레이드오프). → **2026-06-05 v4로 확정(아래).**

### 2026-06-05 — 밀도 조정 v4 (복도 3m · 방 축소 · 밴딧 광장)
- **질문**: 복도 4m→3m·방 축소 시 (1) 맵 크기는? (A. 전체 축소 / B. 44×56 유지+블록 두껍게), (2) 첫 전투(밴딧 코너) 폭은? (A. 3m 균일 / B. 코너만 작은 광장)
- **결정**: **(1) B — 44×56 유지 + 건물블록을 두껍게**(복도/방만 깎고 그 자리를 블록이 메움), **(2) B — 밴딧 코너만 5×5 작은 광장**(복도는 3m 균일).
- **세부**: 복도 전 구간 4m→**3m**. 폐상점 14×10→**11×8**, 창고 14×6→**12×6**, 진입공터(APPR) 6×8→**4×7**. 외곽 벽 5개·스폰(6,3)·맵 크기 불변 → 통합 오프셋(§2.1) 그대로.
- **근거**: 좀보이드式 조밀 골목 체감(복도 3m). 맵을 줄이는 대신 블록을 키우면 통합 좌표/오프셋이 안 흔들리고 두꺼운 건물 매스로 밀도가 올라감. 첫 전투만은 회피(구르기) 공간이 필요해 코너를 5×5로 틔움(메모의 "전투 공간 트레이드오프"를 국소 해소).
- **메모**: 정확 수치는 "실제 배치 보고 결정" 원칙대로 씬 육안 확인 후 미세조정 여지.

### 2026-06-06 — 파밍 실내화 + 창고→맨홀 동선 순서 (v5)
- **피드백(사용자)**: "파밍 지역을 가급적 건물 내부에 넣어라. 스토리상 창고 열고 그다음 조금 가면 맨홀인데, v4는 맨홀이 창고보다 앞에 있어 안 맞는다."
- **결정(방향)**: ① **파밍 포인트는 건물 내부(실내) 위주**(story S-005 ① "가까운 건물 선반·서랍"). v4의 야외 "버려진 도로 박스"는 실내로 이전. ② **동선 순서를 창고 → (조금 더) → 맨홀로 교정**(v4는 APPR 맨홀이 창고보다 앞이라 어긋남 → 창고 셔터·민이·쪽지를 먼저, 그 다음 맨홀).
- **근거**: story-script S-005(파밍=건물 선반/서랍, 창고=클라이맥스) → S-006(창고 다음 맨홀 추출) 순서 정합. 좀보이드式 실내 루팅 체감.
- **realize(확정 v5)**: **창고 통과형**(셔터→창고→북쪽으로 나가면 맨홀 = 창고 너머) + **야외 1곳**(버려진 도로 차 트렁크). 실내 파밍 2방(폐상점·차고). 좌표는 아래 배치 명세/변경 로그.

### 2026-06-06 — 파밍은 '들어가는 건물' 안 + 창고도 건물 (v6)
- **피드백(사용자)**: "건물 안에 파밍 지역이 있어야 하는데 지금 길가에밖에 없다. 창고 건물도 있어야 한다."
- **문제**: v5의 파밍 방(폐상점·차고)이 복도가 **관통하는 통과형**이라 길가 확장처럼 읽힘(=길가 루팅). 창고도 음(陰)의 공간 방이라 '건물'로 안 읽힘.
- **결정(방향)**: 파밍을 **출입문(gb_door)으로 들어가는 독립 '건물'**(폐쇄 footprint + 1칸 출입구) 안에 배치. 길(street)은 건물 **옆**을 지나고, 플레이어가 문으로 건물에 들어가 루팅 후 나온다. **창고도 폐쇄 건물**(셔터 출입). 야외 차 1곳 유지.
- **realize(확정 v6)**: **창고 = 막다른 폐쇄 건물**(셔터 1입구) + **맨홀은 길가 공터**(창고 옆, 보고 나와 길 따라 조금 더 위). 파밍 3건물(폐상점·차고·창고) 각 **출입문(gb_door) 1칸으로만 연결되는 막다른 공간**. 길=서측 세로 3m 골목, 건물은 동측. 빌더 v6=38오브젝트. (아래 §1·배치 명세 좌표표는 v6 씬 레이아웃 육안 확인 후 일괄 갱신.)

### 2026-06-06 — 비-사각(유기적) 리디자인 + Zone1 통합 (v7)
- **피드백(사용자)**: Zone1 coarse 골격을 보고 "크기는 적당한데 **너무 사각형**인 것 같다. **튜토리얼 지역으로 쓸 곳부터** 구성하자." → 격자형 사각 링이 단조로움.

## 1. 폐상가 (안전 구간) — 데모 구역 v5 (확정 — 스토리 MQ-001 첫 출격 동선)

> **용어(2026-06-08 story.md 동기화)**: 낮/밤 설계 폐기 → **안전 구간**(MQ-001, 본 데모) / **짙은 현상 구간**(MQ-002, 지하 루디). 아래 본문의 옛 "낮/밤" 표기는 이 구간 개념으로 읽을 것. **민이 = MQ-001에서 찾는 별개 인물(동생 아님)** — 동생(노을)은 ②지역부터.

> 데모 구역 = **스토리 그대로의 일방통행(LINEAR) 선형 동선**. 분기 없는 단일 복도가 구역을 스토리 순서대로 관통.
> [story-script.md](story-script.md) **S-004~S-006(첫 안전 구간 레이드)** 동선을 1:1로 realize한다:
> **철문 진입 → 폐상점(실내 파밍) → 버려진 도로(차) → 밴딧 광장(첫 전투) → 차고(실내 파밍) → 창고(민이·노크규칙·쪽지, 통과) → 맨홀 탈출(창고 너머).**
> 이력: v2(추상 구역명) 폐기 → v3 스토리화 → v4 복도 4m→3m·방 축소(밀도) → **v5 파밍 실내화 + 창고 통과형(맨홀을 창고 너머로)**. 맵 44×56 유지. 상세는 하단 변경 로그.

### 1.1 컨셉
- **한 줄**: 빽빽한 폐(廢)상가 사이 **좁은 골목 하나**를 따라 남→북으로 관통하는 첫 레이드 동선. **창고**가 목표, **창고를 통과해 그 너머 맨홀**로 탈출.
- **핵심 감정**: "코너를 돌 때마다 뭐가 있을까?" — 길은 외길이라 안 헷갈리되, 지그재그 코너가 시야를 끊어 긴장(밴딧 = 코너 조우).
- **학습 목표(스토리 순)**: 이동/시야 → 루팅(폐상점 실내) → 길가 파밍(버려진 도로, 차) → 전투(밴딧 코너) → 실내 파밍(차고) → 문 통과(창고 셔터) → 단서/민이(창고) → 탈출(맨홀, 창고 너머).
- **시간 목표**: 1회 관통 ~3~5분. 스토리상 "작은 건물 2~3채 + 버려진 도로, **좁고 단순한 첫 지역**"(S-005).
- **스토리 핵심**: 창고에 **민이의 흔적**(셔터 아래 마른 손자국 + 안에서 긁은 자국) + 벽의 **노크 규칙**("세 번 두드리면 대답해…") + **쪽지/단서**. **민이 = MQ-001에서 찾는 별개 인물(동생 아님).** 흔적·노크규칙·쪽지는 분위기/단서 떡밥일 뿐, 동생(노을)은 ②지역부터 (story.md §4 "민이 — 동생 복선과 **별개** 인물").

### 1.2 규모
- **데모 구역 크기**: **44 × 56m** (스토리 "좁고 단순한 첫 지역" — v2 48×58에서 더 압축).
- 타일 1m. 좌표: 남(Y=0)=**철문 진입**(전당포/안전가옥에서 도착), 북(Y=56)=심부(약국 방향, 바리케이드로 봉쇄).
- **탈출 = 창고 너머(북쪽) 맨홀**. 동선은 남→북으로 깊어지다 **창고를 통과(셔터→민이·쪽지)한 뒤 그 북쪽 맨홀 공터에서 추출**.
- **골목/복도 폭 = 3m** 일정(밴딧 코너만 5×5 광장, 첫 전투 회피 공간). **파밍은 실내 방 2곳**(폐상점 11×8·차고 10×7) + 야외 1곳(도로 차). 방은 작고 조밀. 복도/방 외 공간은 전부 **건물블록(filled gb_wall)** — 맵 44×56 유지를 위해 블록을 두껍게 채움.

### 1.4c 지역1 전체 건물 리스트 (확정 2026-07-07 — 탐험 루틴 순 + 회전 배치 원칙)

> **전제 3가지**: ① 모든 건물 = **같은 맵, 천장 페이드 인/아웃**(`CeilingFader`, 씬 전환 X) — 진짜 다층 없음, '하강'은 **같은 평면의 별도 구획 + 조명·연출** ② **스폰 랜덤 / 탈출 = 고정 1 + 랜덤 2, 스폰과 원거리** ③ **고정 동선은 튜토리얼 첫 1회뿐** — 이후 튜토 골목도 랜덤 체계 경로망의 일부.

**건물 11채** = 튜토 3 + 랜드마크 3 + 밀도 점포 5. 아래 순서 = 대표 루틴 1판(남→북), 실제 배치 = 회전 원칙(하단).

## 2. 전체 지역1 통합 관계 (필수 — 나중에 합쳐짐)

> 이 데모 구역은 **독립 씬이 아니라, 전체 폐상가(1000×900) 랜드마크#1 "상가 골목"의 핵심부**다.
> 통합 시 충돌을 막기 위해 **처음부터 통합을 전제로 제작**한다.

### 2.1 데모 구역 ↔ 전체맵 대응
- 전체맵 상가골목 랜드마크#1: footprint **X 140~360 (폭220) × Y 100~300 (폭200)**, 중심 (250,200), 위험 ★ ([`world-map.md`](world-map.md) §7-5, 1000×900 기준).
- 데모 구역(v5 44×56m)은 이 footprint의 **핵심부**. 통합 시 주변(북·동)으로 확장되며 다른 랜드마크로 이어진다.
- **제작 좌표 규칙**: 데모는 **로컬 원점(0,0)~ (44,56)** 기준으로 제작 → 통합 시 **월드 오프셋을 더해** 그 위치에 배치(`world = local + offset`). 데모 맵을 맵툴 "맵 저장"으로 **프리팹화**해 두면 전체 InGameScene의 상가골목 위치에 그대로 인스턴스 가능.
- **잠정 오프셋(통합 시 확정)**: 데모 S1 local(6,3) → 전체 S1 world(200,80)에 맞추면 offset ≈ **(194, 77)**. (1000×900 기준. 정밀값은 통합 시점에 footprint 보고 확정)

### 2.2 데모 전용 → 전체 통합 시 전환
| 데모(지금, v5) | 전체 통합 시 |
|---|---|
| 단일 스폰(철문) S1(남 (6,3)) = **전당포/안전가옥 연결 게이트** | 전체 6스폰 중 상가골목 인접분(S1). 남쪽 = 안전가옥(전당포) 방면 진입로로 유지. 나머지 스폰은 타 랜드마크 쪽 |
| **창고 너머 맨홀 탈출 E0(12,51.5)** | 전체 고정 E0 / D 체계로 통합·재배치. **맨홀 = 안전가옥 복귀 + 짙은 현상 지하창고(루디)와 연결되는 수직 통로**. 데모는 단일 추출 |
| **북단 바리케이드(약국) / 창고 동측 Basement_Block** | **연결로/입구로 개방** — 북단 `Pharmacy_Barricade_N`→**약국**(SQ-002, ★★) 방면 도로로 뚫림 / `Basement_Block`→**짙은 현상 지하창고(루디)** 입구 개방(짙은 현상 구간 phase) |

### 2.3 ⚠️ 레벨 디자인 제약 (지금 반영해야 함)
- **막다른/경계는 "치울 수 있는 잔해/바리케이드"로 막을 것.** v3의 통합 연결점 바리케이드 2곳을 영구 벽이 아니라 **철거 가능한 gb_barricade**로 두어, 치우는 것만으로 인접 랜드마크 연결로/밤 입구가 된다.
  - **Pharmacy_Barricade_N** — **맨홀 공터 북단**(12.5, 54.5) size 7×1 → 치우면 **북쪽 약국**(SQ-002 "폐상가 북쪽 무너진 약국") + 심부 폐상가 방향 개방. (북벽 X8~18 갭이 맨홀 공터 너머에 열려 있음.) **★ 전체맵 연결 관문(확정 2026-06-06)** — 1지역 1000×900으로 나가는 **유일 출구**([world-map.md](world-map.md) §7-5 STEP 2 §E: 약국→상가골목 심부→A1 남부대로·A3 서부종단).
  - **Basement_Block** — 창고 **동측 안쪽**(16, 46) size 1×4 → 짙은 현상 구간 phase에 치우면 **지하창고(루디) 입구** 개방(S-022, 낮엔 봉쇄). 밤 전용 컨텐츠 훅.
- **남쪽 = 안전가옥(전당포) 진입**: 남단 철문 스폰은 **바리케이드 없이 열린 게이트**(전당포에서 도착하는 입구). 통합 시에도 남쪽은 안전가옥 방면 진입로로 유지.
- **출구 방향 일관성**: 북→약국/심부, 창고 동측→밤 지하, 남→안전가옥 방향을 미리 의식하고 바리케이드/게이트를 그쪽 벽에 배치(개방 여지 확보).
- **루트 밀도 스케일**: 데모 단독 밀도는 "첫 레이드 한 줄 관통"용. 전체 통합 시엔 랜드마크 4개 합산이라 **구역당 밀도를 전체 기준으로 재조정** 필요(데모 값은 통합 시 낮춰질 수 있음).

### 2.4 변하지 않는 것 (통합 무관)
- 낮/밤은 **같은 지오메트리 + phase 이벤트**(조명·NPC·루트·적 교체). 통합과 별개. (밤엔 `Basement_Block`이 지하창고 입구로 열림 = 같은 맵의 phase 변화.)
- 구역 위험 위계(철문<폐상점≈도로<밴딧 코너<차고<창고)와 리스크-리워드 곡선은 전체에서도 유지.

- **조밀화 원리**: 복도/방은 건물블록 사이의 **음(陰)의 공간**으로 비워진다. 즉 방 외곽에 얇은 벽을 두르는 대신, **복도/방을 제외한 전 내부를 큰 블록으로 채워** 벽이 자연 형성된다(블록끼리 겹침 무방, 단 복도/방과는 겹치지 않게 클립). **복도 폭 = 3m 일정**(밴딧 코너만 5×5 광장). v5는 채널 9개의 여집합을 12블록으로 재타일(1m 그리드 전수 검증: 채널 무침범 + 빈틈없는 피복).

## 2026-07-11 — 도로 장애물 + 막힌 통로 (`BlockedPassage`)

> 사용자: *"못 가는 지역이나 돌아가야 하는 등의 인터랙티브한 것도 추가해줘"* → 이어서 *"난 도로의 장애물 개념을 말한 건데"*.

### ① 도로 장애물 (주력) — `ObstacleRun`

또 **스폰·탈출·건물 입구 반경은 건너뛴다**(`KeepOut`) — 거기 잔해가 깔리면 스폰하자마자 끼거나 문이 막힌다.

### ② 막힌 통로 — 신규 `Scripts/Interaction/BlockedPassage.cs`
길목에 **솔리드 콜라이더**로 서서 통행을 끊는다. 4가지 모드:

| 모드 | 여는 법 | 배치 |
|---|---|---|
| **Permanent** | 없음(안내만) | 세로 간선 중간 **무너진 고가도로** — 맵의 척추가 끊긴다. 남↔북은 지선·순환으로 우회 |

## 2026-07-11 — 블록 채우기 재작성 (빈 공간 제거 · 골목이 골목으로 읽히게)

### 원인 두 가지
1. **`Shops()`가 크기 풀에서 뽑아 쓰고 남으면 버렸다.** `while (x1-x >= 8f)` 루프라 행·열 끝마다 최대 8m 자투리가 통째로 비었고, 그 자투리들이 골목과 이어지면서 **블록 안이 그냥 넓은 들판**이 됐다. 골목(3m)이 자투리(8m)와 구분되지 않으니 "골목 구성"으로 안 읽힌다.
2. **속 빈 사각 링만 늘어놨다.** 탑다운에서 링은 위에서 내부가 다 보여 '건물'이 아니라 **'선'** 으로 읽힌다. 튜토 구역만 빽빽해 보였던 이유가 정확히 이것 — 거기만 **속이 찬 블록**(`Bldg_*`)을 쓴다.

### 조치
- **블록을 남김없이 분할한다.** 열·행 수를 먼저 정하고 **남는 길이를 필지에 되돌려 준다**(필지 합 + 골목 = 블록 크기, 오차 0). 자투리 개념 자체가 사라진다.
- 필지 크기는 **가중치(0.78~1.23, 합=1)** 로 흔들어 균일 격자처럼 보이지 않게 한다.
- **필지의 55%는 속이 찬 덩어리**(통과 불가). 나머지만 링 + 문 + 진입 발판.
  → 도시의 '살'이 생기고, 들어갈 수 있는 문이 줄어 **한 채 한 채가 의미 있어진다**.
- 이제 블록 안의 음영(negative space)은 **오직 골목뿐** — 골목이 골목으로 읽힌다.

### 개활 블록(공원·주차장)도 채운다
개활 블록이 **그냥 빈 땅**이라 "빈 공간" 체감의 큰 몫이었다. 버려진 차를 주차 열로 깔아 **엄폐가 있는 개활지**로 만든다 — 시야는 트이되 몸은 숨는 곳. 군데군데 빈 자리를 남겨 주차 구획처럼 보이게 하고, 키오스크·유니크 건물 자리는 건너뛴다.

적용: `빌드 ▸ 지역1`

## 2026-07-11 — ★생성 단위 재정의: 필지(lot) → **둘레형 블록(perimeter block)**

> 사용자가 레퍼런스(Streets of Tarkov 맵)를 제시: *"이런 느낌"*

### 레퍼런스가 말하는 것 — 색이 곧 구조
| 색 | 뜻 | 우리 대응 |
|---|---|---|
| 크림 | **건물** — 블록 둘레를 두르는 **꺾인 띠**(L·U·ㄷ자). 정사각형이 사실상 없음 | 지금은 독립 사각형 격자 ❌ |
| 초록 | **안뜰/정원** — 건물이 **에워싼** 블록 내부 | 지금은 그냥 빈 땅 ❌ |
| 짙은 회색 | **길** — 블록 **사이에만** 존재. 블록 안엔 길이 없다 | 지금은 블록 안에도 골목 격자 ❌ |

### 진단 — 여태 틀린 건 '생성 단위'였다
필지(lot)를 잘게 쪼개 각 필지에 네모를 놓는 방식이라, 무엇을 조절해도 **네모의 크기·간격만** 바뀌었다. 밀도를 올리면 다닥다닥, 내리면 텅 빔 — 둘 사이에 답이 없었던 이유다.

레퍼런스의 단위는 **블록 하나**다. 건물은 블록의 **테두리를 따라 두께 8~12m 띠**로 두르고, 그 띠를 3~6조각으로 끊어 각각을 한 채로 삼는다. 조각 경계가 모서리에서 꺾이므로 **L·U자가 저절로 나온다**(정사각형을 "피하는" 게 아니라 애초에 안 생긴다).

### 확정 설계
1. **`PerimeterBlock(블록)`** — `Shops`를 대체.
   - 둘레 띠 두께 8~12m(변마다 다름) → 안쪽은 **안뜰**
   - 띠를 3~6조각으로 분할, 조각마다 문(일부만) — 모서리 조각은 자동으로 L자
   - **아치 갭 1~2개**만 뚫어 안뜰 진입 (골목이 아니라 '통로')
2. **안뜰 = 콘텐츠 공간** — 프랍·루트·적. 에워싸여 있어 교전이 갇힌 싸움이 되고, 들어가는 판단이 필요해진다. 여백이 **'장소'** 가 된다.
3. **블록 = 정체성 단위** — 이름·루트 성격·위험도를 **블록 단위**로(레퍼런스의 색 구분과 같은 역할). 유니크 건물도 블록의 한 조각으로 편입.

> **결정 필요**: 튜토가 실제로 닿게 되면서 `Manhole_Exit`이 **상시 활성 탈출구 2번째**가 된다(`Exit_Fixed`와 함께). 탈출 풀(`PX_*`)에 넣을지, 남서 고정 탈출로 둘지는 미정.

### ④ 노점 골목 통로가 막혀 있었다 (이번에 만든 것)
좌판 칸 경계를 줄마다 따로 잡았더니 두 줄이 벽이 되고, 가운데 통로 양 끝은 아케이드 외벽이라 **들어갈 수 없는 복도**가 됐다.
→ 칸 경계를 **양쪽 줄이 공유**하고 4칸마다 같이 비운다. 그 자리가 가로지르는 통로가 된다.

### 검증 (LayoutSim — 이번부터 **튜토도 검사 대상**)
`ScrapMarketGreyboxLayout`을 시뮬레이터에 포함시켰다. 여기 지오메트리를 손대면서 검사 밖에 두면 ③ 같은 사고를 또 눈으로만 찾게 된다.
- 도달 불가 오브젝트 **0개**(반경 0.35m) — 튜토 내부 포함
- 열린 공간 도달률 **99.9%**, 스폰 9곳 전부 → 탈출 6곳 전부
- 배치: 솔리드 580 / 문 37 / 상자 56 / 쪽지 20 / 적 존 24
- 치울 수 있는 잔해(BlockedPassage 비-Permanent)는 **길로 친다**(대가를 치르면 지나갈 수 있으므로)

### 탈출 규칙 확인 (사용자 질문)
`RaidSpawnDirector`에 그대로 구현돼 있다 — **랜덤 스폰 1 / 고정 탈출 1(항상) / 스폰 반대편 2**.
`Exit_Fixed`는 항상 활성, `PX_SW·SE·NW·NE` 중 매치된 2곳만 활성이고 나머지는 `SetActive(false)`.
매치표(SP1_S→NW·NE, SP2_N→SW·SE, SP3_W→SE·NE, SP4_E→SW·NW, SP5_NE→SW·NW)는 빌더 주석과 디렉터가 같은 값을 갖는다.

### 탈출구 구성 확정 (2026-07-29)

> 질문: 튜토가 실제로 닿게 되면서 `Manhole_Exit`이 상시 활성 탈출구가 된다. 풀(`PX_*`)에 넣을까, 남서 고정으로 둘까?
> **사용자 결정: 남서 고정으로 둔다.**

레이드 한 판의 탈출구는 이제 **4곳**이다.

| 탈출구 | 자리 | 언제 열리나 |
|---|---|---|
| `Exit_Fixed` | 중앙 간선 교차점 | **항상** |
| `Manhole_Exit` | 남서 튜토 구역(맨홀) | **항상** |
| `PX_*` 중 2곳 | 순환도로 네 코너 | 스폰의 **반대편** 2곳만 |

- 중앙 고정 + 남서 고정이라 **가까운 탈출이 항상 두 방향**이고, 매치 2곳이 맵 횡단을 만든다
- 남서 고정은 공짜가 아니다 — 맨홀에 가려면 `Pharmacy_Barricade_N`(철거 가능)을 치워야 하고, **치우면 소음이 난다**. "안전한 탈출로를 미리 열어 둘 것인가"라는 판단이 생긴다

**구현 주의**: 풀에 안 들어간 탈출구는 자동으로 상시 활성이라, 여태 *'일부러 고정으로 둔 것'* 과 *'풀에 넣는 걸 빠뜨린 것'* 을 구분할 수 없었다. → `RaidSpawnDirector.AlwaysOnExtra`에 **의도된 고정 탈출만** 명시한다(매 판 활성 보정도 함께).
`[SerializeField]`로 두지 않은 건 일부러다 — 배열 필드를 새로 직렬화하면 **이미 베이크된 씬**의 컴포넌트가 필드 초기화식을 안 타고 빈 배열이 되어, 고정 탈출이 조용히 사라진다.
