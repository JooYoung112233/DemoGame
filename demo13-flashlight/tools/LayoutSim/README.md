# LayoutSim — 맵 배치 시뮬레이터

그레이박스 빌더(`Assets/Editor/Zone1GreyboxLayout.cs`)를 **Unity 없이 그대로 실행**해서
"못 가는 데가 생겼나"를 즉시 확인한다.

```bash
cd demo13-flashlight/Tools/LayoutSim
dotnet run
```

## 무엇을 하나

1. `Zone1GreyboxLayout.Build()`를 스텁(`Stubs.cs`) 위에서 실행 — 벽·차량·프랍·문·상자·쪽지·적 존 좌표를 전부 기록
2. 0.25m 격자로 래스터화하고 **플레이어 반경만큼 침식**(콜라이더 0.6×0.9 → 0.35m)
3. 스폰 지점에서 **플러드 필** → 도달 못 하는 오브젝트를 전부 출력
4. 스폰 5곳 × 탈출 5곳 도달 여부
5. ASCII 지도(가로 1m / 세로 2m)

## 왜 필요한가

맵 생성기는 값 하나만 바꿔도 **통로가 막힌다**. 그런데 그 사고는 화면에서 잘 안 보인다 —
멀리서 보면 멀쩡하고, 직접 그 골목까지 걸어가 봐야 안다.

실제로 이 도구가 처음 돌았을 때 **식물원 돔(시그니처 랜드마크 ★★★★★)이 통째로 도달 불가**였다.
돔의 유일한 입구는 벽의 '갭'이라 `_keepOut`에 없었고, 간선 갓길에 주차된 버스(9.4m) 두 대가
그 앞을 완전히 덮고 있었다. 눈으로는 몇 달을 봐도 못 찾았을 종류의 버그다.

## 판정 기준

- **도달 불가 오브젝트 = 0** 이어야 한다. 하나라도 있으면 그 루트/문은 존재하지 않는 것과 같다
- 열린 공간 도달률은 99% 이상 (튜토 구역은 별도 파일이라 시뮬레이션에서 빈 땅으로 잡힌다)
- 스폰 5곳 전부가 탈출 5곳 전부에 닿아야 한다

## 한계

- `ScrapMarketGreyboxLayout`(튜토)·`Zone1Interiors`(내부 씬)는 스텁이라 검사 대상이 아니다
- 프리팹의 실제 콜라이더가 아니라 **빌더가 준 크기**로 검사한다(그레이박스는 둘이 같다)
- 씬을 만들지 않는다 — 순수 기하 검사

## 새 빌더를 검사 대상에 추가하려면

`LayoutSim.csproj`의 `<Compile Include="../../Assets/Editor/...">`에 파일을 추가하고,
그 파일이 쓰는 프로젝트 타입이 `Stubs.cs`에 없으면 시그니처만 흉내내 추가한다
(스텁은 게임 로직을 담지 않는다 — 좌표를 기록하는 게 전부다).
